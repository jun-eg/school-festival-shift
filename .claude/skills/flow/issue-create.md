# issue-create

> 依頼を、1 本 = PR 1 本の大きさで issue にする。

起こした issue の点検は [`/issue-check`](../issue-check/SKILL.md) の手である。**起こす手と判定する手を分ける。** この skill は `issue-reviewer` を回さない。

- **入力**: 依頼の文（会話の中で決まった内容でもよい）。目的が読み取れなければ、起こす前に人に 1 つだけ聞く
- **出力**: 起こした issue の番号と URL（親なら親と sub-issue の全部）、または「起こさない」理由とまとめる先

## 守る原本

次はそれぞれの原本を開いて従う。ここに写さない。

| 何を | 原本 |
| --- | --- |
| 本文の書き方・長さ | [`docs/README.md`](../../../docs/README.md) の「issue 本文」節と「長さ」の表 |
| 大きさの物差し | 同「issue 1 本の大きさ」 |
| 本文の雛形 | [`.github/ISSUE_TEMPLATE/issue.md`](../../../.github/ISSUE_TEMPLATE/issue.md) |

## 手順

### 1. 依頼を「変更の単位」に割る

依頼を読み、別々に merge しても成り立つ変更を数える。物差しの定義は原本のとおりに当て、ここで言い換えない。
重複を避けるため、近い issue が既にないか先に探す。

```
gh issue list --state open --search "<依頼の語>" --json number,title
```

### 2. 大きさで分ける

| 原本の表で当てた結果 | すること |
| --- | --- |
| 適切 | 手順 3（単独）へ |
| 大きすぎる | 手順 4（親と sub-issue）へ |
| 小さすぎる | 手順 5（起こさず返す）へ |

### 3. 単独の issue を起こす

1. 本文を scratchpad に書く。雛形の見出しと順に従い、上段は「何に困っている・何をする・どうなったら終わり」の順、長さは原本の表に収める
2. 「終わりの判定」は、起こした後に確かめられる形で書く（誰が何を打つと何が見えるか）
3. 下段の「決めたこと」「却下したこと」は、依頼の対話に出た分だけを書く。出ていない案を先回りして足さない
4. 起こす

   ```
   gh issue create --title "<タイトル>" --body-file <scratchpad>/<名前>.md
   ```

5. 出た URL の issue を `gh issue view <N> --json body --jq .body` で読み返し、先頭数行を確かめる

### 4. 大きすぎる依頼を親と sub-issue に分けて起こす

1. 変更の単位ごとに sub-issue の本文を書く（手順 3 の 1〜3）。各 sub-issue が単独で終わりの判定を持つこと。持たない単位は、隣の単位と合わせてから 1 本の sub-issue にする。合わせ先が決まらなければ手順 5 と同じく人に返す
2. 親の本文を書く。親は大きさを測らない（原本）。上段の「やること」に sub-issue を実装する順で並べる。順が要る理由があれば下段に書く。親の「終わりの判定」は、束ねた結果として何が言えるか
3. 親 → sub-issue の順に起こす。親の「やること」の行には、sub-issue を起こして番号が出てから番号を入れる
4. sub-issue を親に結ぶ。REST の `sub_issue_id` は issue 番号ではなく id である。親の「やること」に並べた順に 1 本ずつ結ぶ（結んだ順が sub-issue の並びになる）

   ```
   gh api repos/<owner>/<repo>/issues/<sub 番号> --jq .id
   gh api -X POST repos/<owner>/<repo>/issues/<親番号>/sub_issues -F sub_issue_id=<上で出た id>
   ```

5. 親の「やること」に番号を入れる必要があれば、自分が起こした親に限り `gh api -X PATCH repos/<owner>/<repo>/issues/<親番号> -F body=@<ファイル>` で当ててよい（`gh issue edit` は使わない）。当てたら先頭を読み返す

### 5. 小さすぎる依頼は起こさずに返す

起こさない。次を人に返す。

- 小さすぎると見た理由（単独では何が言えないか）
- まとめる先の候補。手順 1 で探した既存の open issue、または今回の依頼のほかの変更と合わせた新規 1 本
- 合わせた場合の「やること」「終わりの判定」の案

まとめる先を決めるのは人である。合わせた 1 本として起こすと決まったら、手順 3 から起こし直す。既存の issue の本文は、この skill では書き換えない。

### 6. 報告する

起こしたもの（番号・タイトル・親子）か、起こさなかった理由とまとめる先を返す。続けて「`/issue-check <番号>` で点検できる」と添える。この skill が回しはしない。

## 守ること

- 物差しと本文の規約は原本を開いて従う。この skill に定義や数値を写さない
- 判定しない。`issue-reviewer` を回さず、`/issue-check` は人か、この skill を呼んだ側が打つ
- 書き換えてよいのは、今この skill が起こした issue だけ。既存の issue の本文・タイトル・ラベル・state は触らない
- 小さすぎは起こさずに返す。人の確認なしに既存の issue へまとめない
- 本文は `--body-file` か `-F body=@path`。`-f body=@path` は使わない
- 人名を書く欄は、埋める根拠がなければ空欄にする
