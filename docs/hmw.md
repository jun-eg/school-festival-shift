# HMW — 学祭シフト作成システム

> 課題を『私たちはどうすれば〜できるだろうか？』という問いに変換し、そこから解決策を決める。

アイデア出しフレームワーク 3 ステップの **2 つ目**。手順は
[`.claude/skills/hmw/SKILL.md`](../.claude/skills/hmw/SKILL.md) が持つ。

```
ユーザージャーニーマップ  →  【HMW】  →  Design Doc
```

- **入力**: [`docs/journey/入る側.md`](journey/入る側.md) と [`docs/journey/作る側.md`](journey/作る側.md)
  の改善機会リスト **2 本を 1 つの候補プール**として見る（統合リストは作らない）
- **出力**: このファイル — 採用するソリューション **1 つ** ＋ 採らなかった候補とその却下理由

**HMW は立場ごとに回さない。** 作るシステムは 1 つなので、1 回だけ回して採用案も 1 つに決める。

## 凡例

- 記号（◎ / ○ / △ /（記録））と (n/m) の数え方は
  [`.claude/skills/user-journey-map/references/evidence.md`](../.claude/skills/user-journey-map/references/evidence.md) が持つ

## 選んだ改善機会

> **作る側 改善機会 1. 割り当てが全工程で唯一かつ最大のボトルネックになっている ◎**
> 根拠: 3〜6 時間・3 日がかり・やり直し 20 回規模
> 効く先: ACTION 8

- **出典**: [`docs/journey/作る側.md`](journey/作る側.md) の「確定（◎）」節 — **ACTION 8「シフトを組む（割り当て）」**由来
- **選んだ理由**: 両マップ 68 本を並べたとき、**「どこまでやれば解けたことになるか」を証言から数字で決められる唯一の候補**だから。
  FEELING ADJECTIVE が「果てしない ◎ / 大変すぎる ◎」で振り切れている ACTION はここだけで、
  同じマップの「証言された『理想の状態』」に許容値が書かれている ◎（手作業 5〜15 分 ⇔ 現状 3〜6 時間）。
  他の候補は、重さが ◎ でも許容値が無いか（作る側 17）、許容値があっても総量が小さい（作る側 14）。

## 候補を出す前の足切り

[`docs/journey/作る側.md`](journey/作る側.md) の一次情報で、**HMW に並べる前に潰した方向**。

| 出どころ | 落とした方向 |
| --- | --- |
| すでに試したこと（JSON ＋ リアルタイム表示） | **見える化を強くする方向**。作ったが 3〜6 時間のままだった ◎（作る側 改善機会 9）。同じ方向の案を採用案にしない |
| 却下した案（自動集計スプレッドシートのプレビュー共有） | 重複行とスマホの見づらさで却下済み ◎。そもそも改善機会 1 に効かない |
| 却下した案（Google フォームにログイン設定） | API 制限の副作用込みで却下済み ◎。そもそも改善機会 1 に効かない |
| 証言された「理想の状態」 | **全自動で確定版まで出す方向**（求められていない ◎）／**出入口を LINE から動かす方向**（置き換え対象は割り当ての中身だけ ◎）／**手作業が 5〜15 分に収まらない方向** ◎ |
| 作る側 改善機会 21 | **前年の成果物を再利用する方向**。準備開始／調理開始／調理終了／片付け開始の 4 時刻が日ごと・年度ごとに変わる ◎ |

**足切りした方向も、候補としては書いて残す**（後工程の Alternatives Considered で「なぜ違うのか」に答える必要があるため）。

## ソリューション候補

### 候補 A: 条件を外に出して「仮完成」を 1 案生成し、担当者は例外だけ直す

- 対応する問い: I1・I3 / H1 / D2 / E1・E2
- 内容: いま担当者の頭の中にある入力（調理担当者名簿・調理責任者の学年・希望時間・委員会の指定枠・
  準備／片付けのルール・役割ごとの必要人数）を**データとして外に出し**、条件を満たす割り当てを **1 案生成する**。
  担当者はその 1 案を直す側に回る。公平の指標（合計時間・シフト回数・準備回数）は生成時に計算して並べる
- 効く改善機会: 作る側 1・2・3・4・5・8

### 候補 B: 候補の絞り込みだけを機械にやらせ、誰を入れるかは担当者が決める

- 対応する問い: C2 / G1 / A2 / F3
- 内容: 枠を選ぶと、検便 ◎・学年 ◎・希望時間 ◎ の 3 条件を満たす人だけが、合計時間の少ない順に出てくる。
  担当者はその中から選んで置く。**「探す」を機械に、「決める」を人に**割る

### 候補 C: 制約チェッカー（人が組み、違反と偏りを機械が指摘する）

- 対応する問い: B1 の裏返し
- 内容: 割り当ては今までどおり人が JSON で組み、検便・学年・時間の違反と、合計時間の偏りを画面に出す

### 候補 D: 締切前から暫定の割り当てを回し続ける

- 対応する問い: A1 / F2 / H2
- 内容: 希望が 1 件届くたびに暫定の割り当てを更新し、締切時点ではほぼ出来ている状態にする。
  締切後の出し直しや遅れた提出も、同じ操作を 1 回足すだけで吸収する

### 候補 E: 希望を最初から 30 分枠で集めて、変換工程を無くす

- 対応する問い: C1 を入力側から
- 内容: フォームを粗い単位ではなく 30 分枠で聞く形に変え、担当者の頭の中にある「粗い希望 → 30 分枠」の割り直し ◎（作る側 5）を消す

### 候補 F: 前年のシフト表をテンプレートとして流用し、差分だけ直す

- 対応する問い: F2 / D1
- 内容: 引き継がれる前年のシフト表 1 枚を雛形として読み込み、今年の名簿と希望で差し替える

### 候補 G: 捨てている友達欄 24 件を、割り当ての選好として使う

- 対応する問い: F1
- 内容: 条件を満たす候補が複数いるとき、友達欄に書かれた学籍番号 ◎（記録 24/24 が機械可読）を使って
  同じ枠に寄せる。期待が乗っているのは提出の 6 割 ◎（記入 24/39）なので、そこだけでも期待と結果を合わせる

### 候補 H: 割り当てを分担する／手順書を残す

- 対応する問い: G2 / I2
- 内容: 調理系と非調理系で担当を分ける。頭の中のルールを手順書に落として、技術力に依らず同じ手で組めるようにする

### 候補 I: 入る側が自分で 30 分枠を取る（セルフサービスの枠取り）

- 対応する問い: B2 / H1 を入る側に振り切った版
- 内容: 担当者が割り当てるのをやめ、空いている枠を入る側が自分で取る。担当者は埋まらなかった枠だけを埋める

### 候補 J: 全自動で確定版まで出す（人の微修正を挟まない）

- 対応する問い: I3 を振り切った版
- 内容: 生成した割り当てをそのまま確定版として配布し、担当者の手作業を 0 にする

## 採用するソリューション

**候補 A: 条件を外に出して「仮完成」を 1 案生成し、担当者は例外だけ直す**

採用理由。

- **証言された理想の形にそのまま重なる** ◎ — 「全自動は求められていない。仮完成 → 手で微修正が前提に入っている」
  「許容できる手作業は 5〜15 分」。候補 A は担当者の役割を「組む」から「直す」に移す案なので、この 2 行を**同時に**満たしにいける。
  **他の候補は、どちらか片方しか満たさないか、どちらも満たさない**
- **ボトルネックの正体に当たっている** — 重さの中身は、3 条件（検便 × 学年 × 時間）で候補が枯れる探索 ◎（作る側 2）と、
  一箇所直すと別が崩れる 20 回のやり直し ◎（作る側 1）である。**人が苦手で機械が得意な部分が、そのままボトルネックになっている**
- **すでに効かなかった手と方向が違う** — JSON ＋ リアルタイム表示は「表として見える」ところまでで、3〜6 時間は変わらなかった ◎（作る側 9）。
  候補 A は見せ方ではなく、**工程そのものを人から外す**
- **ルールを外に出す作業が副産物を持つ** — 頭の中にある割り当てルール ◎（作る側 3）・公平の基準 ◎（作る側 4）・
  粗い希望の変換 ◎（作る側 5）をデータにしないと成立しない案なので、**着手そのものが 3・4・5 の解消になる**
- **出入口を動かさない** ◎ — 集める口（Google フォーム）と配る口（LINE ノート）はそのまま。置き換えるのは割り当ての中身だけ

### 採用案が満たすべき条件（作る側 17 から）

**作る側 17 は「解く対象」としては落としたが、条件としてここに残す。**
17 は「毎年 1 人の持ち回り ◎」の担当者が担ぐという話なので、
**技術力の高い年にしか成立しない形で作ると、対象者が証言者 1 人になる。**

- 担当者に要求してよいのは**入力だけ**で、スクリプトを書ける・正規表現を書けることを前提にしない
- 担当者が自作した資産（バリデーション付きフォーム・識別キー・整備スクリプト）は**3 つとも「渡らない」◎** である。
  **その出力を暗黙の入力前提に置かない**

**ここから先（この条件をどう満たすか・どのセクションに書くか）は Design Doc の仕事である。**
HMW は問いと候補の段階なので、設計まで降ろさない。

## 採らなかった候補と却下理由

**消さずに残す。** [`docs/design-doc-template.md`](design-doc-template.md) の Alternatives Considered の入力になる。

| 候補 | 却下理由 |
| --- | --- |
| **候補 B: 候補の絞り込みだけ機械にやらせる** | **「5〜15 分 ◎」に構造的に届かない。** 枠は 4 日分 × 30 分刻み ◎ で、1 枠に調理責任者 1・調理 2・会計 1・呼び込み 2・列整理 2 ◎ が要る。**置く操作の回数が数百に乗るので、1 回がどれだけ速くても許容値を超える。** さらに「一箇所直すと別が崩れる」20 回 ◎（作る側 1）は、崩れたことに人が気づく前提のままなので残る。**「仮完成 → 微修正」◎ の仮完成が出てこない** |
| **候補 C: 制約チェッカー** | **すでに試して効かなかった方向である** ◎（作る側 9）。JSON ＋ リアルタイム表示で「見える」ところまでは到達済みで、それでも 3〜6 時間だった。違反を指摘しても、条件に合う候補を探して 20 回組み直す作業 ◎ は人に残る |
| **候補 D: 締切前から暫定を回し続ける** | **候補 A の上に乗る運用であって、A の代わりにならない。** 暫定を何度も回すには「1 回が安い」ことが前提で、それを作るのが候補 A である。生成器が無いまま回数を増やすと 3〜6 時間が掛け算になる。加えて、締切内の出し直し 11 件は**自動で畳まれていて作る側の手間として見えていない** ◎（作る側 34）ので、**この案が減らす手間が作る側に立っていない** |
| **候補 E: 希望を 30 分枠で集める** | 消えるのは変換工程（作る側 5）だけで、**重さの本体である組合せ探索（作る側 2）が丸ごと残る**。加えて、**一意さを要求すると入る側が止まる** ◎（入る側 25。学籍番号で書いた 1 人が友達の学籍番号確認で止まっている (1/5)。記録上の記入者はもう 1 人いる ◎ が、その人が手間を口にしたかは聞いていない △ なので (1/5) のまま）。提出はスマホが多数 ◎ (3/5) なので、細かい枠を選ばせる方向は**入る側のコストで作る側の時間を買う**形になる |
| **候補 F: 前年のシフト表を流用** | **成立しない** ◎（作る側 21）。準備開始／調理開始／調理終了／片付け開始の 4 つの時刻が日ごと・年度ごとに変わるため、前年の枠が今年に乗らない。そもそも引き継がれるのは完成した表 1 枚だけで、**割り当ての根拠は載っていない** ◎（作る側 15） |
| **候補 G: 友達欄 24 件を選好に使う** | **改善機会 1 の下流である。** 捨てている理由は「余裕がなく考慮していない ◎」（作る側 6）なので、**割り当てが軽くならない限り、拾う余裕そのものが生まれない**。材料の側は整っている — 書かれた 24 件は**全件が指定どおりの学籍番号 ◎（記録 24/24）**で、書式の揺れは無い。一方で**空欄が 15/39 ◎ あり、その内訳（弾かれて諦めたのか、最初から書く気がなかったのか）は記録では区別できない △**（→ `ADR 入る側-0012` / `ADR 作る側-0006`）。**4 割弱が対象外のまま残る案を主軸には置けない。** 候補 A が入ったあとの上積みとして残す |
| **候補 H: 分担する／手順書を残す** | 分担は総量 3〜6 時間を**分けるだけで減らさない**。担当は押し付けか持ち回りで決まり、無報酬で他の役割と兼任している ◎（作る側 23）ので、担ぐ人を増やす前提が置けない。手順書は**作る側 15・17 には効くが、改善機会 1 の時間には効かない** — 手順が書いてあっても、3 条件で候補が枯れる探索 ◎ と 20 回のやり直し ◎ は同じだけ掛かる |
| **候補 I: 入る側のセルフサービス枠取り** | 検便・調理責任者の学年・委員会指定枠を**入る側に守らせることになり**、違反枠と空き枠の検査が結局作る側に戻る。入る側は 5 人とも希望どおりに入れており ◎ (5/5)、いまの出す側の体験は壊れていない。**壊れていない側のコストを上げて作る側の時間を買う案である** |
| **候補 J: 全自動で確定版まで出す** | 証言された理想に正面から反する ◎（「全自動は求められていない」）。公平の基準は担当者の頭の中にあって確かめる手段が目視しかなく ◎（作る側 4）、しかも**量を均しても公平感には届かない** ◎（入る側 14 / → `ADR 入る側-0010`）。最後の一手を人に残す方が安全である |
