# HMW — 学祭シフト作成システム

> 課題を『私たちはどうすれば〜できるだろうか？』という問いに変換し、そこから解決策を決める。

アイデア出しフレームワーク 3 ステップの **2 つ目**。手順は
[`.claude/skills/hmw/SKILL.md`](../.claude/skills/hmw/SKILL.md) が持つ。

```
ユーザージャーニーマップ  →  【HMW】  →  Design Doc
```

- **入力**: [`docs/journey/入る側.md`](journey/入る側.md) と [`docs/journey/作る側.md`](journey/作る側.md)
  の改善機会リスト **2 本を 1 つの候補プール**として見る（統合リストは作らない）
- **出力**: このファイル — 採用するソリューション **1 つ** ＋ 採らなかった候補とその却下理由

**HMW は立場ごとに回さない。** 作るシステムは 1 つなので、1 回だけ回して採用案も 1 つに決める。

## 凡例

- 記号（◎ / ○ / △ /（記録））と (n/m) の数え方は
  [`.claude/skills/user-journey-map/references/evidence.md`](../.claude/skills/user-journey-map/references/evidence.md) が持つ
- 改善機会の番号は**マップごとに独立**しているので、**「入る側 N」「作る側 N」と立場を付けて**参照する

## 選んだ改善機会

> **作る側 改善機会 1. 割り当てが全工程で唯一かつ最大のボトルネックになっている ◎**
> 根拠: 3〜6 時間・3 日がかり・やり直し 20 回規模
> 効く先: ACTION 8

- **出典**: [`docs/journey/作る側.md`](journey/作る側.md) の「確定（◎）」節 — **ACTION 8「シフトを組む（割り当て）」**由来
- **選んだ理由**: 唯一 FEELING ADJECTIVE が「果てしない ◎ / 大変すぎる ◎」で振り切れている ACTION であり、
  同じマップの「証言された『理想の状態』」に**解くべき距離が数字で書かれている** ◎（許容できる手作業 5〜15 分 ⇔ 現状 3〜6 時間）。
  ここだけが「どこまでやれば解けたことになるか」を証言から決められる

| --- | --- | --- |

| 友達欄が考慮される前提で書かれているのに捨てられている | 入る側 2・23 / 作る側 6 | 「余裕がなく捨てている ◎」が理由なので、割り当てが軽くならない限り着手できない。**改善機会 1 の下流である** |
| 1 件の変更の反映に 10 分かかる | 作る側 14 / ACTION 10・11 | 件数が 4 日間で 5 件以下 ◎。総量が 3〜6 時間に比べて小さい |

## 候補を出す前の足切り

[`docs/journey/作る側.md`](journey/作る側.md) の一次情報で、**HMW に並べる前に潰した方向**。

| 出どころ | 落とした方向 |
| --- | --- |
| すでに試したこと（JSON ＋ リアルタイム表示） | **見える化を強くする方向**。作ったが 3〜6 時間のままだった ◎（作る側 改善機会 9）。同じ方向の案を採用案にしない |
| 却下した案（自動集計スプレッドシートのプレビュー共有） | 重複行とスマホの見づらさで却下済み ◎。そもそも改善機会 1 に効かない |
| 却下した案（Google フォームにログイン設定） | API 制限の副作用込みで却下済み ◎。そもそも改善機会 1 に効かない |
| 証言された「理想の状態」 | **全自動で確定版まで出す方向**（求められていない ◎）／**出入口を LINE から動かす方向**（置き換え対象は割り当ての中身だけ ◎）／**手作業が 5〜15 分に収まらない方向** ◎ |

## HMW の問い

「私たちはどうすれば〜できるだろうか？」の形で書き殴ったもの。**型は全部埋まったが、採用案に効いたのは下 4 行である。**

| 型 | 私たちはどうすれば〜できるだろうか？ |
| --- | --- |
| Amp up the good | すでに効いている「JSON を見ながら直す」体験を、どうすれば工程の**入口**まで広げられるだろうか？ |
| Explore the opposite | どうすれば割り当てを**最大限やりにくく**できるだろうか？（→ ルールを頭の中だけに置き、候補を見せず、直すと他が崩れる状態。**裏返すと**「ルールを外に出す・候補を見せる・崩れた所だけ示す」になる） |
| Remove the bad | どうすれば、一箇所直すと別が崩れるやり直しを、担当者がやらずに済むようにできるだろうか？ |
| Create an analogy | どうすれば、時間割の自動生成や経路案内のように「**まず 1 案が出てきて、そこから選び直す**」体験にできるだろうか？ |
| Identify unexpected resources | 手元にあるのに使い切れていない材料（調理担当者名簿・希望データ・委員会の指定枠・前年の完成表）で、どうすれば割り当ての当たりを付けられるだろうか？ |
| Break the point-of-view into pieces | どうすれば、候補が枯れる調理系と自由度の高い非調理系を、**別々の難しさ**として解けるだろうか？ |
| Go after the adjective | どうすれば「果てしない」割り当てを、**一息で終わる**作業にできるだろうか？ |
| Change a status quo | どうすれば、担当者の仕事を「**組む**」から「**出てきたものを直す**」に変えられるだろうか？ |
| Question an assumption | そもそも、最初の 1 枚を人が組む必要があるだろうか？ |

## ソリューション候補

### 候補 A: 制約を機械可読にして「仮完成」を自動生成し、担当者が手で微修正する

- 対応する問い: Question an assumption / Change a status quo / Go after the adjective / Create an analogy
- 内容: いま担当者の頭の中にある入力（調理担当者名簿・調理責任者の学年・希望時間・委員会の指定枠・
  準備／片付けのルール・役割ごとの必要人数）をデータとして外に出し、**制約を満たす割り当てを 1 案生成する**。
  担当者はその 1 案を直す側に回る。公平の指標（合計時間・シフト回数・準備回数）は生成時に計算して並べて見せる
- 効く改善機会: 作る側 1・2・3・5・8（ルールを外に出す作業がそのまま 3・5 の解消になる）

### 候補 B: 制約チェッカー（人が組み、違反と偏りを機械が指摘する）

- 対応する問い: Amp up the good
- 内容: 割り当ては今までどおり人が JSON で組み、検便・学年・時間の違反と、合計時間の偏りを画面に出す

### 候補 C: 希望を最初から 30 分枠単位で集めて、変換工程を無くす

- 対応する問い: Remove the bad
- 内容: フォームを粗い単位でなく 30 分枠で聞く形に変え、担当者の頭の中にある「粗い希望 → 30 分枠」の割り直しを消す

### 候補 D: 前年のシフト表をテンプレートとして流用し、差分だけ直す

- 対応する問い: Identify unexpected resources
- 内容: 引き継がれる前年のシフト表 1 枚を雛形として読み込み、今年の名簿と希望で差し替える

### 候補 E: 割り当てを複数人で分担する／手順書を残す

- 対応する問い: Identify unexpected resources / Break the point-of-view into pieces
- 内容: 調理系と非調理系で担当を分ける。頭の中のルールを手順書に落として、翌年以降も同じ手で組めるようにする

### 候補 F: 入る側が自分で 30 分枠を取る（セルフサービスの枠取り）

- 対応する問い: Explore the opposite / Change a status quo
- 内容: 担当者が割り当てるのをやめ、空いている枠を入る側が自分で取る。担当者は埋まらなかった枠だけを埋める

### 候補 G: 全自動で確定版まで出す（人の微修正を挟まない）

- 対応する問い: Remove the bad を振り切った版
- 内容: 生成した割り当てをそのまま確定版として配布し、担当者の手作業を 0 にする

## 採用するソリューション

**候補 A: 制約を機械可読にして「仮完成」を自動生成し、担当者が手で微修正する**

採用理由。

- **証言された理想の形にそのまま重なる** ◎ — 「全自動は求められていない。仮完成 → 手で微修正が前提に入っている」
  「許容できる手作業は 5〜15 分」。候補 A は担当者の役割を「組む」から「直す」に移す案なので、この 2 行を同時に満たしにいける
- **ボトルネックの正体に当たっている** — 重さの中身は 3 条件（検便 × 学年 × 時間）で候補が枯れる探索 ◎（作る側 2）と、
  一箇所直すと別が崩れる 20 回のやり直し ◎（作る側 1）である。**人が苦手で機械が得意な部分がそのままボトルネックになっている**
- **すでに効かなかった手と方向が違う** — JSON ＋ リアルタイム表示は「表として見える」ところまでで 3〜6 時間は変わらなかった ◎（作る側 9）。
  候補 A は見せ方ではなく、**工程そのものを人から外す**
- **ルールを外に出す作業が副産物を持つ** — 頭の中にある割り当てルール ◎（作る側 3）と粗い希望の変換 ◎（作る側 5）を
  データにしないと成立しない案なので、着手がそのまま 3・5 の解消になる
- **出入口を動かさない** ◎ — 配布は LINE ノートのまま。置き換えるのは割り当ての中身だけ

### この案が解かないもの

**改善機会 1 に絞った採用である。** 以下は候補 A の射程外なので、Design Doc のスコープで改めて扱う。

| 残るもの | 立場・番号 |
| --- | --- |
| 1 件の反映に 10 分かかる（理想の「修正ループも 5〜15 分」に届かない） | 作る側 14 |
| 作り込みが翌年に残らない | 作る側 15・16・17 |
| 当日運用（サボりの肩代わり・遅刻が次の枠に乗る） | 作る側 24・25 / 入る側 12・13・15 |
| 友達欄が捨てられている | 作る側 6 / 入る側 2・23 |

### 一次情報との照合

| 照合先 | 結果 |
| --- | --- |
| 却下した案（スプレッドシート共有 / フォームのログイン設定） | **反しない**。どちらも再提出していない |
| 理想「全自動は求められていない」 | **反しない**。仮完成を出すところまでで、確定は人が行う |
| 理想「許容できる手作業は 5〜15 分」 | **反しない**。微修正がこの幅に収まることが、この案の達成条件になる |
| 理想「出入口は LINE のまま」 | **反しない**。集める口（Google フォーム）と配る口（LINE ノート）は変えない |
| すでに試したこと（JSON ＋ リアルタイム表示） | **同じ方向ではない**。見える化の強化ではなく、割り当て工程そのものの置き換えである |

## 採らなかった候補と却下理由

**消さずに残す。** [`docs/design-doc-template.md`](design-doc-template.md) の Alternatives Considered の入力になる。

| 候補 | 却下理由 |
| --- | --- |
| 候補 B: 制約チェッカー | **すでに試して効かなかった方向である** ◎（作る側 9）。JSON ＋ リアルタイム表示で「見える」ところまでは到達済みで、それでも 3〜6 時間だった。違反を指摘しても、候補を探して 20 回組み直す作業は人に残る |
| 候補 C: 希望を 30 分枠で集める | 消えるのは変換工程（作る側 5）だけで、**重さの本体である組合せ探索（作る側 2）が丸ごと残る**。加えて、入力項目を増やすと入る側が止まる ◎（入る側 25。指定を守った 1 人が友達の学籍番号確認で止まっている）。提出はスマホが多数 ◎ (3/5) なので、細かい枠を選ばせる方向は入る側のコストで作る側の時間を買う形になる |
| 候補 D: 前年のシフト表を流用 | **成立しない** ◎（作る側 21）。準備開始／調理開始／調理終了／片付け開始の 4 つの時刻が日ごと・年度ごとに変わるため、前年の枠が今年に乗らない。そもそも引き継がれるのは完成した表 1 枚だけで、**割り当ての根拠は載っていない** ◎（作る側 15） |
| 候補 E: 分担する／手順書を残す | 分担は総量 3〜6 時間を分けるだけで減らさない。担当は押し付けか持ち回りで決まり、無報酬で他の役割と兼任している ◎（作る側 23）ので、担ぐ人を増やす前提が置けない。手順書は作る側 15・17 には効くが、**改善機会 1 の時間には効かない** |
| 候補 F: 入る側のセルフサービス枠取り | 検便・調理責任者の学年・委員会指定枠を**入る側に守らせることになり**、違反枠と空き枠の検査が結局作る側に戻る。入る側は 5 人とも希望どおりに入れており ◎ (5/5)、いまの出す側の体験は壊れていない。**壊れていない側のコストを上げて作る側の時間を買う案である** |
| 候補 G: 全自動で確定版まで出す | 証言された理想に正面から反する ◎（「全自動は求められていない」）。公平の基準は担当者の頭の中にあって確かめる手段が目視しかなく ◎（作る側 4）、しかも**量を均しても公平感には届かない** ◎（入る側 14 / → ADR 入る側-0010）。最後の一手を人に残す方が安全である |
