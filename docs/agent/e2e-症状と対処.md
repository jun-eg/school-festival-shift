# E2E（`npm run e2e`）が実機で止まる事象 — 症状と切り分けと対処

作成: 2026-10-25（jun-eg ／ Claude）。[issue #331](https://github.com/jun-eg/school-festival-shift/issues/331) の表の #307（PR #337）の行にある 3 つを、**実機で起こさずに受け入れた**（人の決定）。代わりに、実装を読んで症状と対処をここに置いた。**2026-10-25 に [#331](https://github.com/jun-eg/school-festival-shift/issues/331) で実機を通し、Execution API の返事（HTTP 200 の `Error: `・日次上限・存在しない関数・Drive の 403）は「実機で見た」に置き換えた**（記録は [`src/real-device-log.md`](../../src/real-device-log.md) の「画面で見た結果」）。**A・B・C の 3 つ自体は、起こしていないので推測のままである。** その後に直った 1 つ（E）と、日次上限の控えの注意（F）を足した。

ID・トークン・GCP プロジェクト ID の値はここに書かない（公開リポジトリ）。`~/.clasprc.json`・OAuth クライアントの JSON・`.env` は表示もコピーもしない（→ [`e2e/README.md`](../../e2e/README.md)）。

## A. OAuth 同意画面が「テスト」の間、7 日で clasp のトークンが切れる

### 何が起きるか（仕組み）

用意するもの 1 で、OAuth 同意画面は「外部・テスト」にしてある。**公開状態が「テスト」のアプリが出したリフレッシュトークンは 7 日で失効する**（Google の仕様。スコープがメールアドレス・プロフィールだけのときは除く。ここは spreadsheets・script・drive.file を含むので当たる）。トークンは `~/.clasprc.json` にあり、[`google.mjs`](../../e2e/google.mjs) の `accessToken` が、そのリフレッシュトークンでアクセストークンを取る。`clasp push` も同じファイルを使う。**同意画面を「本番」にすると切れないが、検証専用の個人のプロジェクトでは、そのためのアプリの審査は受けない前提である**（人が選ぶ）。

### 疑われる症状

- 実装から引いた（実行の最初の API 呼び出し、`assertSandbox` で出る。**何も書かずに止まる**）:
  `E2E を回せなかった: access token が取れない: invalid_grant（…）。clasp login をやり直す`
  `（…）` の中は Google の `error_description`。失効のときは `Token has been expired or revoked.`（推測。実機で見ていない）
- 実装から引いた: `~/.clasprc.json` が無い・壊れているときは `clasp の認証が読めない（<パス>）。人が 1 回 clasp login --creds を通す`
- 推測: clasp 単体（`clasp push` だけを人が打ったとき）は、`invalid_grant` か、再ログインを求める旨のメッセージを返す。e2e は先に自前の API 呼び出しで止まるので、`npm run e2e` では clasp 側の文言まで届かないはず。

### 切り分け方

1. 出力が `access token が取れない: invalid_grant` なら A である。ほかの原因（クライアントの削除・パスワード変更・アカウントのアクセス取り消し）でも同じ文言が出る
2. 最後に `clasp login` した日を見る。7 日を超えていれば A でほぼ確実（`ls -l ~/.clasprc.json` の更新日時は、トークンの更新で動くことがあるので当てにしすぎない）
3. [Google アカウントの「サードパーティ アクセス」](https://myaccount.google.com/connections)に、検証用のアプリが残っているか

### 対処

- **人の手が要る**（ブラウザの承認）: 用意するもの 3 を、そのままもう一度打つ。
  `npx clasp login --creds <JSON のパス> --use-project-scopes --include-clasp-scopes --extra-scopes https://www.googleapis.com/auth/spreadsheets`
  承認が済めば、あとは `npm run e2e` が無人で回る。7 日たつたびに繰り返す
- Claude ができるのは、症状を上の表で切り分けて「再ログインが要る」と人に伝えるところまで。承認は人
- **根本の避け方**: 同意画面を「本番」にする（審査が要るスコープが無いか、未検証アプリの警告を受け入れる）。ただし E2E は任意であり、このために本番にする決定はしていない

### 確かめていないこと

- **7 日で切れること**を、この repo の実機で起こして見ていない（Google の仕様の記述に頼る）
- 再ログイン後に無人へ戻ることを、失効した状態から見ていない（ログインし直せば新しいトークンになる、という理解）
- 失効時の `error_description` の文言と、`clasp push` 単体の文言

## B. 検証用スクリプトと GCP プロジェクトの結び付けが外れる

### 何が起きるか（仕組み）

Execution API（`scripts.run`）は、**呼ぶ側の OAuth クライアントが属する GCP プロジェクトと、スクリプトの GCP プロジェクトが同じ**でなければ通らない。結び付けは Apps Script エディタの「プロジェクトの設定 → Google Cloud Platform プロジェクト」でしか変えられない（用意するもの 2）。スクリプトを作り直した・エディタで別のプロジェクトに付け替えた・GCP プロジェクトを消した、で外れる。**`.env` の `SFS_E2E_GCP_PROJECT` は必須の項目だが、コードのどこも値を使っていない**（[`env.mjs`](../../e2e/env.mjs) の `required` に名前があるだけ）。だから結び付けのずれを事前には検出しない。

### 疑われる症状

- 実装から引いた: `push` までは通る（`assertScriptBelongsToSandbox` が見るのは親のスプレッドシートで、GCP の結び付けは見ない。`clasp push` は Script API で、結び付けと関係なく通る見込み）
- 実装から引いた: 最初の `scripts.run`（`build-template.e2e.mjs` の 1 回目の `buildTemplate`）で、`buildTemplate が失敗した（HTTP <status>）: <本文>` となり、**再試行しない**（5xx・429・`reading from storage`・`timed out`・`Service invoked too many times` 以外）
- 推測: status は 403、本文は権限の不足を述べる文（`The caller does not have permission` 系）。404（`Requested entity was not found.`）の可能性もある。**実機で起こしていない。**実際の status と本文は、起きたらこの節に写す
- 実装から引いた: テストは最初の呼び出しで落ち、続く検査は走らない

### 切り分け方

1. 出力の `HTTP` と本文を控える（Claude が読む。トークンは出力に出ない）
2. A でないことを確かめる（A なら、これより前の `access token が取れない` で止まる。ここまで来ていれば、トークンは生きている）
3. エディタ（スプレッドシート → 拡張機能 → Apps Script → プロジェクトの設定）で、「Google Cloud Platform プロジェクト」の番号が、OAuth クライアントを作ったプロジェクトの番号と同じか見る
4. GCP の側で、Apps Script API が有効か（Execution API の呼び出しにも要る）を見る
5. スクリプトを手で 1 回、エディタから走らせて、承認が済んでいるかを見る（承認が切れていると別の症状になる）

### 対処

- **人の手が要る**: 用意するもの 2 をやり直す（エディタの「プロジェクトの設定」で、GCP プロジェクトの番号を入れ直す。結び付けはエディタでしかできない）
- 付け替えたあと、**Claude ができる**: `npm run e2e` をもう一度回して通ることを見る
- スクリプトを作り直したなら、新しいスクリプト ID を `.env` の `SFS_E2E_SCRIPT_ID` に入れる（人。値は表示しない）

### 確かめていないこと

- 結び付けを外して `scripts.run` を打ったときの **status と本文**（上の 403・404 は推測）
- 外したあとも `clasp push` と `assertScriptBelongsToSandbox` が通ること（コードの読みと Google の仕様の理解から）
- 付け替えた直後に、反映が遅れて同じ症状が続くことがあるか

## C. 呼び出しが 180 秒で切れる — 再試行で二重に走らないか

### 何が起きるか（仕組み）

[`gas.mjs`](../../e2e/gas.mjs) の `callFunction` は、関数 1 回を `AbortSignal.timeout(180_000)` で切り、**切れたら 5 秒待って 1 回だけ再試行する**（通信の失敗・5xx・429・`reading from storage`・`timed out`・`Service invoked too many times` が対象）。

**切るのは Node の待ちだけである。Apps Script 側で走っている実行は止まらない**（実行の上限は 6 分）。だから**最悪の場合、1 回目がまだ走っている間に、2 回目が同じスプレッドシートの上で始まる**。これが「二重に走る」の意味で、起きるのは 1 回目が 180 秒を超えたときだけである。

実機の所要時間は、`buildTemplate` が数十秒以内、`e2eGenerate` が 4〜10 秒（実機で見た: [`src/real-device-log.md`](../../src/real-device-log.md) の項目 14）で、180 秒に遠く届いていない。**切れるのは、Google 側の遅延・停止のときに限る**。

### 4 つの関数が 2 回走ったとき（コードから読んだ。実機では起こしていない）

「順に 2 回」は、1 回目が終わってから 2 回目が始まる場合（Node が先に諦めたが Apps Script は終えていた）。「重なる」は、1 回目の実行がまだ続いている間に 2 回目が始まる場合。

| 関数 | 順に 2 回 | 重なる | 困るか |
| --- | --- | --- | --- |
| `buildTemplate` | **冪等**。「足りないものだけ足す」作りで、見出し・初期値・幅・保護を同じ形に置き直す。2 回目は「作った」も「見出しを置いた」も出ない（実機で見た: 項目 3、2026-09-20）。初期値は区画が空のときだけ置く | 同じ名前のシートを両方が `insertSheet` しようとして、片方が失敗する、保護が二重に付く、のどちらかが起こりうる（推測）。ただし 2 回目が終われば、次の `buildTemplate` が同じ形に直す | 困らない（形は 2 回目か次の 1 回で揃う）。重なりは推測 |
| `e2eGenerate`（`run`） | **冪等**。構造を確かめ、入力を読み、コアで組み、出力のシートを**消して書き直す**。同じ入力から同じ案が出る（実機で見た: 項目 15）。マス目の手直しの印は、2 回目が読んで引き継ぐ | 2 本が同じ範囲を書き直す。最後に書いた方が残る（書き方は「消して書く」なので、混ざって壊れる可能性は推測） | 困らない（結果を捨てて作り直せる）。時間と日次の回数だけ食う |
| `createFormFromPicker`（`buildFormOn`） | **2 回目は止まる**。1 回目が完走していれば「回答」シートにフォームの URL があるので、`このファイルにはもうフォームがあります（<URL>）。前年のファイルのコピーなら、…「来年用に空にする」を押してから、もう一度「フォームを作る」を押してください` で例外になる。**フォームは増えない**。1 回目が途中（`FormApp.create` の後、`linkAnswerSheet` の前）で落ちていて、「回答」の元のシートにまだ URL が無ければ、2 回目は**もう 1 つフォームを作る**（推測。`setDestination` 後は「フォームの回答 1」が残るので、2 回目はそれを数えずに新しい 1 枚を探す） | **フォームが 2 つできる**。互いの `setDestination` と `linkAnswerSheet` が競り、回答のシートが 2 枚できて、`フォームが作った回答シートが N 枚ある（1 枚のはず）` で止まるか、片方のフォームが孤児になる | **困る**。フォームが残る・条件入力 C9・C10 の URL が 2 回目で上書きされて 1 つ目の URL を失う |
| `e2eClearForNextYear`（`clearForNextYearOn`） | **冪等**。2 回目は `「回答」はフォームに紐付いていなかった` と記録して、返す `formUrl` は `null`。「回答」は消して作り直し、割り当て・検証結果・指標・URL 欄は空にするだけなので同じ形になる | 「回答」を両方が `deleteSheet`→作り直し、で競う。シートが無い・同名が 2 枚、で止まりうる（推測） | **順になら困らない。ただし返り値が変わる**: 1 回目の `formUrl`（外したフォーム）が結果から消えるので、e2e は `cleared.formUrl` を見る検査で落ち（`pipeline.e2e.mjs`）、そのフォームをこの回では捨てない。ただし作った直後に控え（`.e2e/leftover-form.json`）へ書いてあるので、次の回の頭で拾って捨てる |

まとめ。**二重に走っても困らないのは `buildTemplate` と `e2eGenerate`**（冪等で、やり直せる）。**困るのは `createFormFromPicker`**（フォームが増える・孤児になる）で、**`e2eClearForNextYear` は形は同じでも、外したフォームの URL が結果から消える**。

**`createFormFromPicker` と `e2eClearForNextYear` を再試行しない、という変更の候補**は、この文書では決めない（実機で切れた例を見ていない。見たら、その時の関数と所要時間で決める）。

### 疑われる症状

- 実装から引いた（Node の中。`callFunction` の `catch` が拾い、1 回目の後に 5 秒待つ）: 1 回目と 2 回目のどちらもタイムアウトなら、最後の例外がそのまま出る。文言は Node の `fetch` の中断のもの（推測: `The operation was aborted due to timeout`）
- 実装から引いた: 2 回目が Google に受け付けられて失敗したら `<関数名> が失敗した（HTTP <status>）: <本文>`
- **実機で見た（2026-10-25）**: スクリプトの例外は、HTTP の status が **200** で、本文の `error.details[0].errorMessage` が **`Error: ` 付き**で返る。再試行の対象ではないので 1 回で止まる。見た文言: `e2eGenerate が失敗した（HTTP 200）: Error: シートの見出しや列が 1 か所変わっているため…`、`createFormFromPicker が失敗した（HTTP 200）: Error: 「回答」シートにすでに 1 行あるため、フォームを作れません…`。`createFormFromPicker` を 2 回目で打てば `このファイルにはもうフォームがあります…` が同じ形で出るはずである（コードから。この文言そのものは e2e では起こしていない）
- **実機で見た（2026-10-25）**: 存在しない関数は `… が失敗した（HTTP 200）: Script function not found: …` で 1 回で止まり、再試行しない
- 日次の上限は F

### 切り分け方

1. 出力で、どの関数が・何回目で・何の文言で止まったかを見る
2. Apps Script のエディタの「実行数」（左の列）で、その関数の実行が何本・いつ・何秒かを見る。**2 本あれば二重に走った**。1 本なら、2 回目は届かなかった
3. スプレッドシートを開いて、シートの数・並び・「回答」の URL 欄（条件入力 C9・C10）・「フォームの回答 N」という余分なシートが無いかを見る
4. ドライブで、題名がスプレッドシートと同じフォームが何本あるかを見る（`createFormFromPicker` のとき）

### 対処

- `buildTemplate`・`e2eGenerate` のとき: Claude が、そのまま `npm run e2e` をもう一度回す。実行の頭が空に戻すので、残りは効かない
- `createFormFromPicker`・`e2eClearForNextYear` のとき:
  1. **Claude ができる**: 余分なフォームを、`npm run e2e` の次の回の頭に任せる（控えと C10 から拾って捨てる）。拾えないものは、フォームの編集用 URL を人が見つけて渡せば、`e2e/drive.mjs` の `trashForm` で捨てられる
  2. **人の手が要る**: 控えにも C10 にも残っていない孤児のフォームは、ドライブで題名から見つけて、ゴミ箱へ移す。「フォームの回答 N」という余分なシートは、スプレッドシートの「回答」タブの ▼ →「フォームのリンクを解除」を押してから消す
  3. 検証用スプレッドシートがおかしくなっていれば、`npm run e2e` の頭の「空に戻す」（`resetSpreadsheet`）が、シート 1 枚の空にする。この回の残りは、それで消える
- 同じことが何度も起きるなら、Google 側の障害か、スクリプトが重くなっている。Apps Script のステータスを見る

### 確かめていないこと

- 実機で、180 秒で切れたことは**一度も無い**。2 回走った実測もしていない
- 「重なる」の振る舞い（シートの競り・保護の二重・フォームの競り）は、全てコードからの推測である
- 切れた後の Apps Script の実行が、本当に 6 分まで続くか（Execution API の仕様の理解）
- `createFormFromPicker` の「途中で落ちる」窓が、実際にどれだけ起きうるか

## D. 初回の呼び出しだけ `reading from storage … NOT_FOUND` が返り、1 回の再試行で通る

実機で見た（`e2e/README.md` にも書いてある）。`clasp push` の直後の最初の `scripts.run` で、devMode が保存版を読むところが間に合わず、
`<関数名> が失敗した（HTTP <status>）: …reading from storage … NOT_FOUND`（status は記録していない）が返る。
`callFunction` はこの文言を一時的なものとして 5 秒後に 1 回だけやり直し、通る。止まらないので、人も Claude も何もしない。

- **この再試行が C の「二重」を起こす心配は無い**: 実行が始まる前に落ちているので、1 回目は何も書いていない（最初の呼び出しは `buildTemplate` で、どのみち冪等である）
- 2 回目でも同じ文言が出るなら、`clasp push` が届いていない（push 先のスクリプト ID が `.env` と合っているか）か、B（結び付け）を疑う。そのとき status が 404 なら、B の推測が当たっている可能性がある
- 確かめていないこと: 1 回の再試行で通らなかった例があるか（見ていない）。NOT_FOUND の status の値

## E. 続けて回すと、前の回の紐付けと一時シートで頭が落ちる（直した）

**実機で見て、#349 で直した。**

- 症状: 前の回の流れが途中で終わった・最後まで通ったあとで、続けて `npm run e2e` を回すと、頭の `resetSpreadsheet`（シート 1 枚の空に戻す）で落ちた。原因は、前の回の「回答」にフォームの紐付けが残り、フォームが作った一時のシートが残っていたこと。
- 直したこと: 流れの最後で「回答」の紐付けを外し、頭で、紐付いた全シート（「回答」だけでなく）の紐付けと、一時シートの残りを拾ってから空に戻す。
- 紐付いたシートが「回答」以外の名前（「フォームの回答 1」など）で残った形も、頭で拾う（#349 の `b481127`。紐付けを外し、残ったフォームを 1 件ゴミ箱へ移す。実機で、その形から 24/24 で通ったのを見た。続けてもう 1 回回しても、拾いのログ無しで 24/24）。
- 拾えずに、それでも頭で落ちるとき（**人の手が要る**）: スプレッドシートの「回答」タブの ▼ →「フォームのリンクを解除」を押し、余分な「フォームの回答 N」のシートを消してから、もう一度回す。

## F. Execution API と Drive の止まり方（実機で見た）

**実機で見た（2026-10-25）。出力の文言は次のとおり。**

- **日次上限**: 控えの回数が 100 に達していれば、呼ぶ前に上の文で止まり、`scripts.run` を打たない。
- **控えは `~/.config/sfs-e2e/quota.json` に 1 つ**（#352 で直した。worktree をまたいで効く）。**日付は日本時間で、0 時に 0 へ戻る。** 別の worktree（352・351）から回した分が 1 つの控えに積まれた（日本時間 2026-10-25 で 34 → 50）。同時に回しても数え違えないよう、控えのそばの `quota.json.lock`（`~/.config/sfs-e2e/` の中）で排他にする（持ち主が落ちて残ったものは 10 秒で奪う）。上限は、Google 側の本物の上限ではなく、こちらの控えの数である。
- **控えが上限に達したときの文**（`e2e/gas.mjs`）: `今日の scripts.run が上限（100 回）に達した。控えは worktree をまたいで 1 つで、日本時間の 0 時（明日の 0:00）に 0 へ戻るので、その後にやり直す（<控えのパス>）`。ロックが 30 秒取れないときは `控えのロックが取れない（<ロックのパス>）`。
- **ゴミ箱へ移す**（`trashForm`）: フォームでないファイルを渡すと、`ゴミ箱へ移そうとしたものがフォームではない。何もせずに止めた` で止まり、PATCH は打たない。同じファイル（検証用スプレッドシート）へ書き込もうとすれば **403（reason: `appNotAuthorizedToFile`）**。`drive.file` のスコープは、このアプリが作った・開いたファイルにしか効かないためである。
- **未確認**: 403 の案内文が出る経路は、スクリプトが作っていないフォームを用意しないと起こせず、まだ見ていない。
