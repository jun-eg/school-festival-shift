# ADR tech-requirements-0018: 「配布はテンプレートのコピー」は誰が何をどう渡すかを決めておらず、本線（README の `/copy` リンク）と予備（前年のファイルを空にしたコピー）の 2 本になった

- **Status**: 有効
- **Date**: 2026-10-24
- **対象**: `docs/agent/tech-requirements.md` — **6 の #1**（実行形態。採ったもの・却下側の「1 つのファイルを引き継ぐ」）
  ／ `src/clear-for-next-year.js`（新規）／ `src/menu.js`（項目 4 つ目）／ `src/README.md`（「メニューは 1 つである」・「要求するのは 3 スコープである」・「テンプレートの作り方」の手順 10）
  ／ ルートの `README.md`（「次の担当者に引き継ぐ」）／ ルートの `CONTRIBUTING.md`（テンプレートの差し替え）
- **出典**: [issue #260](https://github.com/jun-eg/school-festival-shift/issues/260)（2026-09-23 の実機）／ [issue #290](https://github.com/jun-eg/school-festival-shift/issues/290)

## それまでの結論

**6 の #1 は「配布はテンプレートのコピー」とだけ書いていた。**

> **担当者のドライブに置く 1 つの Google スプレッドシートと、そこにバインドしたスクリプト。**配布は**テンプレートのコピー**。

**誰がテンプレートを持ち、どこに置き、担当者がどこからそれに辿り着くかは決めていなかった。**
[`src/README.md`](../../../../src/README.md) の「テンプレートの作り方」の手順 10 が「**渡す相手には閲覧者で共有する**」と書いているだけで、
**担当者向けの手順書は #159 として参照されていたが、その番号の issue は無かった**（[#260](https://github.com/jun-eg/school-festival-shift/issues/260)）。

**暗に置いていた前提は「使い終わったファイルをコピーすれば、次の年に引き継げる」だった**（#260 の「困っていること」）。

## 何が起きたか

**2026-09-23 に、使い終わった形のファイル（フォームを作り、回答シートにモックの 50 行が入っている）をコピーした**（#260 の「実際に試したこと」）。

1. **回答（氏名・学籍番号）が全行そのままコピーに渡った** — #112 で「1 つのファイルを引き継ぐ」を却下した理由（個人情報が何年ぶんも残る）と同じことが、コピーでも起きる
2. **紐付いたフォームも黙って 1 つ複製され、コピーの回答シートはそれに紐付いた** — コピーのダイアログには何も出ない

**「コピー」と書いただけでは、何をコピーするかで結果が変わることが分かった。**

## 新しい結論

**配り方は 2 本である。担当者の操作は、どちらも「コピー 1 回 ＋ 承認 1 回」のまま変わらない。**

| | 何を置くか | 後任の操作 | 止まるとき |
| --- | --- | --- | --- |
| **本線** | **jun-eg が管理するテンプレートを「リンクを知っている全員が閲覧可」にし、その `/copy` リンクをルートの [`README.md`](../../../../README.md) に置く** | README を開く → `/copy` リンクを押す → 「コピーを作成」を 1 回押す | jun-eg のアカウントが消える／テンプレートの共有を外したとき |
| **予備** | **前年の担当者が、自分の使い終わったファイルをコピーし、メニュー「シフト → 来年用に空にする」を押して渡す** | 渡されたファイルを本線と同じくコピーして使う | — |

- **本線を採る理由** — **jun-eg が管理している間は、直した内容がそのまま次の担当者に届く。**コードを直したら、管理する側がテンプレートのスクリプトを差し替える（→ [`CONTRIBUTING.md`](../../../../CONTRIBUTING.md)。担当者の操作は増えない）
- **予備を持つ理由** — **本線はテンプレートが jun-eg のドライブにあることに頼っている**（6 の #1 の却下側、Web アプリの ② と同じ形）。**前年のファイルから作り直せれば、起案者が抜けても途切れない**
- **テンプレートの決まり** — **テンプレートでは「フォームを作る」を押さない。**押すと回答とフォームがコピー先に渡る（上の 1・2）。**テンプレートに入っているのは条件入力の初期値だけで、氏名・学籍番号は入っていないので、リンクで公開してよい**
- **zip にしない理由** — スプレッドシートとバインドしたスクリプトを 1 つにまとめるファイル形式が無い。zip に入れられるのは `src/` の `.js` と HTML になり、**担当者に Apps Script へ貼らせることになる**（「テンプレートの作り方」そのもので、達成条件 4 を破る）

### 予備は作る — 「来年用に空にする」

**作るか、やめて本線だけにするかを決める項目だった（#290）。作った。**
**やめると、本線が止まった年（テンプレートの持ち主が抜けた年）に、テンプレートを作り直す手（`src/` のファイルを Apps Script へ 1 本ずつ貼る）しか残らない。**
**それは担当者にできる操作ではない**（2 の「担当者がやることの全部」に無い）。**押す 1 回で戻せるなら、そちらが安い。**

**押すと 4 つをやる**（→ [`src/clear-for-next-year.js`](../../../../src/clear-for-next-year.js)）。

1. **回答シートとフォームの紐付けを外す**（`Form.removeDestination`。**スコープは `forms` のままで、増えない**）
2. **回答の行を消す**（今年の題の 4 列の見出しも空け、テンプレートと同じ形に戻す）
3. **割り当て 4 枚・検証結果・指標を、テンプレートの形に戻す**（値・時刻の見出し・手直しの印・色・氏名のプルダウン・前に見たマス目の控え）
4. **条件入力の 9〜10 行目（フォームの URL → [#255](https://github.com/jun-eg/school-festival-shift/issues/255)）を空にする**

**条件入力の値は残す** — **そのまま来年の初期値になる**（→ [`0015`](0015-テンプレートは空ではなくなり条件入力に前回の値が初期値として入った.md)）。

**複製されたフォームは、前年の担当者が手でゴミ箱に移す。** スクリプトで消すにはドライブのスコープが要る（**承認の画面が 1 つ広がる**）。
**押した後の画面が、外したフォームの URL を出して名指しする。**

**押し間違いには 2 つで備える。**

- **メニューの区切り線の下に離して置く**
- **押すと「元のファイルではなく、コピーで押していますか？」の確認が出る** — 元のファイルで押すと、今年の回答が消えるためである

### #112 の却下とどう違うか

**#112 で却下したのは「コピーさせず、1 つのファイルを担当者から担当者へ引き継ぐ」形である。** 理由は **氏名・学籍番号が 1 つのファイルに何年ぶんも残り、残る先が担当者の個人アカウントになりうる** ことだった。

**予備は、それと 2 点で違う。**

| | #112（却下） | 予備 |
| --- | --- | --- |
| **渡るファイル** | **使っていたファイルそのもの** | **使っていたファイルのコピー**で、元のファイルは前年の担当者の手元で終わる |
| **氏名・学籍番号** | **残る**（年をまたいで溜まる） | **消してから渡す**（回答・割り当て・検証結果・指標） |

**渡るのは条件入力の値とスクリプトだけで、本線のテンプレートと同じ中身である。** **#112 の却下理由は、予備には当たらない。**
**#112 の却下は動いていない。**
