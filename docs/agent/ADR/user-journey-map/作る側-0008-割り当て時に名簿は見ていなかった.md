# ADR 作る側-0008: ACTION 8「3 条件を名簿と照合する ◎」が崩れた — 割り当て時に見ているのは自作サイトの申告列だった

- **Status**: 有効
- **Date**: 2026-09-19
- **対象**: docs/journey/作る側.md — ACTION 2・4・6・8・10b（TASK LIST）／「すでに試したこと」の表／「ジャーニーマップ」の呼び名の注／凡例の実施日／「証言を一般化するときの注意」
- **出典**: [issue #100](https://github.com/jun-eg/school-festival-shift/issues/100) のコメント（2026-09-19）／ [`docs/interviews/02-作る側.md`](../../interviews/02-作る側.md)「訂正（2026-09-19）— issue #100」／ 前回のフォームの質問項目データ（issue #97。画像アイテム 1 つ）

## それまでの結論

ACTION 8 の TASK LIST に、こう書いてあった。

> ・**調理系は検便・学年・時間の 3 条件を名簿と照合する ◎**

**「名簿と照合する」は本文にしかなかった。** 改善機会 2 の根拠は「**検便 × 学年（3・4 年）× 時間が合う**の 3 条件で
候補が極端に狭まる」、改善機会 7 の根拠は「**3 条件を再チェック**している」であり、
**どちらも照合相手を名指ししていない。**

呼び名も割れていた。**同じ 1 本の自作サイト**を、ACTION 10b と「すでに試したこと」は「**提出サイト**」、
ACTION 6 は「**提出記録**」と書いていた。**「すでに試したこと」の表に載っていたのは機能の行だけ**（シフト表確認・希望確認画面）で、
**サイト本体の行が無かった。**

## 何が起きたか

**issue #100 が「名簿（ひらがな氏名）と回答（学籍番号）をどう突き合わせるか」を 4 案で立てたところ、
本人がそれを 3 段階で差し戻した**（逐語は [`docs/interviews/02-作る側.md`](../../interviews/02-作る側.md)）。

| # | 出てきた訂正 |
| --- | --- |
| 1 | そもそもフォームに `調理担当ですか？` があるのだから、機械的に突き合わせる必要があるのか |
| 2 | 照合は名簿を見ている。ただし**回答が合っているかの確認ではない**。スプレッドシートに調理／非調理の絞り込みが無いので、**見やすさで**参照している |
| 3 | **名簿ではなく列を見ている。正しくはシフト希望提出履歴サイトである** |

**3 が 2 を打ち消している。** 順序を残さないと、この 1 本は「名簿を見ている（ただし検証ではない）」で止まって読める。

## 新しい結論

**割り当て時に名簿は使われていない** ◎。ACTION 8 の TASK LIST は、こうなった。

> ・調理系は検便・学年・時間の 3 条件を見ながら置く ◎。調理／非調理は**シフト希望提出履歴サイト**の列（＝ `調理担当ですか？` の申告）で読む ◎

**名簿の役割は 1 つだけ残る。**

| いつ | 役割 | 記号 |
| --- | --- | --- |
| **フォーム記入時** | **画像アイテムとしてフォームに貼られている**（設問ではない。回答として回収されない）。本人が `調理担当ですか？` に答えるために見る | ◎（記録。質問項目データ） |
| **割り当て時** | **無い** | ◎（2026-09-19） |

**呼び名は「シフト希望提出履歴サイト」1 つに揃えた** ◎（本人の呼称）。
**表示内容を指すときは「提出履歴」**と書く。同一物と判定した根拠は次の 3 つである。

- **自作サイトは 1 本で、トップに「シフト提出／シフト希望確認／管理者ページ／11 月 1〜4 日シフト表」が並ぶ** ◎（記録。
  → [`docs/interviews/01-入る側.md`](../../interviews/01-入る側.md)。**確認サイトと希望確認画面も、同じサイトの別ボタンである** ◎）
- **希望確認画面がこのサイトの中にある** ◎（記録。ACTION 10b）
- **割り当て時に調理／非調理を読むのもこのサイトである** ◎（訂正 3）

**「すでに試したこと」の表は、このサイトを機能ごとに行で分けてある**（本体 ／ シフト表確認 ／ 希望確認画面）。
**行を畳んでいない** — 目的も「効いたか ◎」も行ごとに違うからである。
**「却下した案」の「提出記録を Gmail に飛ばす機能」だけは別物**（Google フォーム側の通知機能 ◎）なので、揃えていない。

## 影響

- **ACTION 8** の TASK LIST の 1 行を書き直した。**「照合」は検証と読めるので使っていない**
- **ACTION 4** に「調理担当者名簿を**画像としてフォームに貼る** ◎（記録。設問ではない）」を足した。
  **名簿の唯一の役割がどの ACTION に出るかが、本文に無かった**（ACTION 2 で受け取ったきり、出口が書かれていなかった）
- **ACTION 2** の IMPROVEMENT OPPORTUNITIES を「外部ルールの**照合**が全部手作業」→「外部ルールの**適用**が全部手作業」に直した
- **ACTION 6・10b と「すでに試したこと」の呼び名**を「シフト希望提出履歴サイト」に揃えた。
  改善機会 22・27・34 の根拠にある「提出記録」も「提出履歴」に揃えた
- **「すでに試したこと」に「シフト希望提出履歴サイト本体（Vercel）」の行を足した。**
  **割り当て時に調理／非調理を絞って見る先になっていた ◎** という役割が、どこにも載っていなかった
- 「ジャーニーマップ」節の冒頭に**呼び名の注**を置いた。凡例の実施日に **2026-09-19（訂正）**を足し、
  「証言を一般化するときの注意」の「2 回動いている」を **3 回**に直した

## 動いていないもの

- **改善機会は 1 本も動いていない。**
  - **改善機会 2・7 の根拠は「3 条件」としか言っておらず、照合相手を名指ししていない** — 書き換えるものが無い
  - **改善機会 19**（委員会のルールが文書化されず人伝いに渡っている ◎）も動いていない。
    根拠は「検便・学年・クリーンパトロールのどれも口頭か前年度担当者経由 ◎」で、**名簿の使われ方とは別の話**である。
    動いたのは ACTION 2 からこの機会を指していた**一言の言葉づかい**（照合 → 適用）だけである
- **外部制約の表は動いていない。**「検便を通った人だけが調理に入れる ◎」も
  「調理担当者名簿としてフォーム作成前に配布される ◎」も、**そのまま成り立っている**
- **△ は 1 つも増えていない。** 申告が名簿と食い違った記録は無く、**食い違いの検出は Before にも無い**
- **新しい工程は 1 つも足していない**
