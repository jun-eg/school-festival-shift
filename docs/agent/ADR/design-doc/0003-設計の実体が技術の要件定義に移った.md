# ADR design-doc-0003: 6・7 の設計の実体が別の文書に移り、「変換規則は送らない」の明記が取り消された

- **Status**: 有効
- **Date**: 2026-09-19
- **対象**: `docs/design-doc.md` — 6. Functional Requirements（成果物に含めるもの / 複製するフォームの中身 / スコープ内 1〜9 の表 / 希望時間の聞かれ方と変換規則 / 配布形は画像そのものである） ＋ 7. Mile Stone（完了判定に使う前回データ）
- **出典**: issue #105 ／ [`.claude/skills/tech-requirements/SKILL.md`](../../../.claude/skills/tech-requirements/SKILL.md)（「Design Doc との境界」「業務の規則 — 発明を禁止すれば、送れる」）／ PR #106（2026-09-19 マージ。器の新設）

## それまでの結論

**設計の実体が Design Doc の 6・7 に溜まっていた。** 置き場が上流しか無かったからである。
具体的には次の 6 つ。

| どこ | 溜まっていたもの |
| --- | --- |
| 6「成果物に含めるもの」／「複製するフォームの中身」 | 設問 9 つ ＋ 画像アイテム 1 つの表・3 箇所の正規表現の実体・エラーメッセージの句点の揺れ ◎ |
| 6「希望時間の聞かれ方と変換規則」 | 4 設問共通の正規表現の実体・設問の説明文の例と営業時間 ◎・展開規則（区間に完全に含まれる 30 分枠の和集合）・特別扱い 3 つの適用形 |
| 6「配布形は画像そのものである」 | 画像に固定する理由（4-2 の Before = After が要件）＋ 出力形式そのもの |
| 6 スコープ内 1〜9 の表 | 入力の型 7 項目の中身・畳み込みキー（学籍番号 ＋ タイムスタンプ）・準備／片付けルールの具体 |
| 7「完了判定に使う前回データ」 | モック化の規約（置き換えるもの・置き換え先・形式は本物のまま保つ・置き場・対応表は入れない）＋ 加工の順序 |
| 6「希望時間の聞かれ方と変換規則」冒頭 | **変換規則を技術の要件定義に送らないという明記** |

**最後の 1 つは、消す直前にこう書かれていた。**

> **変換規則は、このドキュメントで確定させる。技術の要件定義には送らない。**
> 「粗い希望 → 30 分枠」は担当者の頭の中にある**業務の規則** ◎（作る側 5）であって、実装手段の選択ではない。
> 送ってしまうと、**規則そのものが技術側で発明される**ことになり、
> このドキュメントが守っている「記号の付いた主張だけを引く」から外れる。

## 何が起きたか

**器ができた。** [#104](https://github.com/jun-eg/school-festival-shift/issues/104)（PR #106、2026-09-19 マージ）で
`tech-requirements` skill と [`docs/tech-requirements-template.md`](../../tech-requirements-template.md) が入り、
成果物 `docs/tech-requirements.md` の置き場が決まった。

**「送らない」と書いた理由は、器が無かったことではなく、器が発明を許すことへの不安だった。**
器の側はその不安に名指しで答えている（skill「業務の規則 — **発明を禁止すれば、送れる**」）。

1. この文書は規則を発明しない。書ける規則は**出どころを持つものだけ**（一次記録 ／ 関係者の証言 ／ Design Doc が確定させた判断）
2. **出どころの無い規則は書かない。** 書きたくなったら △ に置いて Design Doc に返す
3. **規則を「こう扱う」と決める判断は、こちらでしない**（特別扱いを設けるか・端をどう切るか・決まらないものを人に返すか）

**3 つとも、送らないと書いた理由をそのまま打ち消している。** したがって不安は解消したと判定した。

## 新しい結論

**設計の実体の原本は [`docs/tech-requirements.md`](../../tech-requirements.md) である。**
Design Doc は判断と裏付けだけを持つ。**「技術の要件定義には送らない」の明記は取り消す。**

### 変換規則は割れる（送らないの取り消し）

**規則そのものが送られたのではない。** 器の「5 つの分かれ目」に沿って割れた。

| どちらに | 中身 |
| --- | --- |
| **Design Doc に残る（判断）** | 重なる枠ではなく**完全に含まれる枠**を採ること（本人が居ない時間に人を置かない）／`00:00-00:00` に**特別扱いを設ける**こと／営業時間外へ伸びた区間を**弾かない**こと／終端 ≤ 始端を**担当者に名指しで返す**こと（黙って解釈しない）／**4 と 5 を分ける**こと |
| **`docs/tech-requirements.md` に来る（適用形）** | 正規表現の実体／展開の適用の順序（区間ごとに営業 4 時刻から刻んだ 30 分枠のうち完全に含まれるものを取り、複数区間は和集合）／境界値の扱いの実体（`10:00-10:15`・`00:00-00:00` は空集合・営業時間外はクリップ・終端 ≤ 始端は候補を作らない） |

**根拠の記号は落としていない。** `00:00-00:00` がセンチネルである根拠（設問の説明文 ◎）、
営業時間外が 3 件・終端 ≤ 始端が 5 件（記録）、終端 ≤ 始端が何を指していたか △ 8 は、
移送先でも記号と出どころ付きで持つ。

### 残り 5 つの割り方

| どこ | 残ったもの（Design Doc） | 移ったもの（`docs/tech-requirements.md`） |
| --- | --- | --- |
| フォームの中身 | **「フォーム定義一式を成果物に含める」という出口の判断** ◎ | 設問 9 つ ＋ 画像アイテム 1 つの表・3 箇所の正規表現・句点の揺れ ◎ → 4. 記録からの転記 |
| 配布形 | **画像に固定する理由**（4-2 の Before = After が要件。判定者の居ない要件は要件ではない） | 出力仕様（画像ファイルである／前回の配布物と同じ粒度／中で何を使って描くかは縛らない）→ 5. 仕様 |
| スコープ内 1〜9 | **何を作るか 9 行** | 入力の型 7 項目の中身・畳み込みキー ◎・準備／片付けルールの具体 ◎ → 3. 業務の規則・5. 仕様 |
| 完了判定に使う前回データ | **判定は形式と件数で決まる／実データも対応表もリポジトリに入れない** | モック化規約の実体と加工の順序 → 7. 検証と完了の測り方 |
| 前提にしている「すでにあるもの」の表 | **全部残る**（裏付けと判断である） | — |

### 動いていないもの

- **達成条件 1〜4・スコープ外 8 行 ＋ 追加 4 つ・△ 1〜8 は 1 行も動いていない**
- **記録の数字 ◎ も動いていない**（39 人 / 50 行 / 6 人分 / 5〜15 分 / 3〜6 時間 / 24・15 など）。
  達成条件の数字とマイルストーンの完了の定義は**上流が原本のまま**で、移送先は引用で置く
- **1〜5 は 1 行も動いていない**
- **7 の日付・窓・M1〜M6 の完了の定義は動いていない**

## 影響

- **6 を書き直した**
  - 「成果物に含めるもの」— フォーム定義の中身の列挙と句点の揺れを**参照に置き換えた**。出口の判断（成果物に含める ◎）は残した
  - **「複製するフォームの中身」の表を丸ごと抜いた**（→ 移送先 4）。「4-2 の 6 項目 ◎ は入る側から見た数え方である」の段落は**残した**（判断である）
  - スコープ内の表 — 1・3・4・8 のセルから**型の中身・畳み込みキー・準備／片付けルールの具体・出力形式**を抜き、参照に置き換えた
  - **「希望時間の聞かれ方と変換規則」を書き直した。** 送らないという明記を**削除**し、
    正規表現の実体・展開の仕方の表・特別扱い 3 つの表を抜いて、**判断だけの節**にした。
    「粗い単位 ◎ の正体 — 選択式ではない」の読み（記録で崩れた話）は残した
  - **「配布形は画像そのものである」から出力仕様を抜き**、理由だけにした
- **7 を書き直した**
  - **「完了判定に使う前回データ」からモック化規約の表と加工の順序を抜き**、
    「判定は形式と件数で決まる／実データも対応表もリポジトリに入れない」の 2 行に縮めた
- **`docs/tech-requirements.md` を新しく起こした**（雛形をコピーした 1 本。ステータス Draft）
- **更新ログに 1 行**足した
- **`docs/ADR/README.md` の表は動かしていない。**`design-doc/` は既に行がある。
  **`docs/ADR/tech-requirements/` は作っていない** — 動いたのは上流の判定であって、生まれたばかりの文書の判定ではない
