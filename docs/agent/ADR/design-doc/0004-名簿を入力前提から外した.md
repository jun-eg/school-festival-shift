# ADR design-doc-0004: 6 が調理担当者名簿を「そのまま入力に取る」と書いていたのが崩れた — 調理可否の出どころは申告である

- **Status**: 有効
- **Date**: 2026-09-19
- **対象**: `docs/design-doc.md` — 4-1. User Story（作る側の Before）／ 6. Functional Requirements（前提にしている「すでにあるもの」の表 ／ 新設「調理担当者名簿を入力前提に置かない」／ スコープ内 1）
- **出典**: [issue #100](https://github.com/jun-eg/school-festival-shift/issues/100) のコメント（2026-09-19）／ [`docs/interviews/02-作る側.md`](../../interviews/02-作る側.md)「訂正（2026-09-19）— issue #100」／ [`ADR 作る側-0008`](../user-journey-map/作る側-0008-割り当て時に名簿は見ていなかった.md)／ 前回のフォームの質問項目データ（issue #97）

## それまでの結論

6 の「前提にしている『すでにあるもの』」の表に、こう書いてあった。

> | **調理担当者名簿**（検便を通った人） | 学祭運営委員会 ◎（フォーム作成前に配布される） | 毎年降りてくる ◎ | **そのまま入力に取る** |

スコープ内 1 も、入力の型を **7 項目**で数えていた。

> 担当者の頭の中にある条件（枠・役割と必要人数 ◎・**調理担当者名簿 ◎**・調理責任者の学年条件 ◎・委員会の指定枠 ◎・準備／片付けのルール ◎・希望）を、**入力として外に出す**

4-1 の Before も、名簿を照合相手として名指ししていた。

> - 調理系は検便 × 学年 × 時間の 3 条件を**名簿と目で照合する** ◎

## 何が起きたか

**上流（ジャーニーマップ）が動いた**（→ [`ADR 作る側-0008`](../user-journey-map/作る側-0008-割り当て時に名簿は見ていなかった.md)）。

**割り当て時に名簿は使われていない** ◎。担当者が調理／非調理を読んでいるのは
**自作のシフト希望提出履歴サイトの列**であり、そこに出ている値は **`調理担当ですか？` の申告**である。
名簿の役割は、**フォームに貼られた画像アイテム**（設問ではなく、回答として回収されない ◎ 記録）として
**本人が申告するために見る**ことに尽きる。

**issue #100 は起票時、「名簿と回答をどう突き合わせるか」を 4 案（A 自己申告を正とする／B 氏名で join する／
C 名簿に学籍番号を足す／D スコープ外に出す）で立てていた。**
**本人の差し戻しで、その判断そのものが存在しなかったことが分かった** — 案 A は **Before の写し**であり、
**行動の差がゼロ**である。

## 新しい結論

**調理担当者名簿を入力前提に置かない。**

| 名簿をどう扱うか | |
| --- | --- |
| **入力に取るか** | **取らない。**割り当て時に参照されていない ◎ |
| **成果物に含めるか** | **フォームに貼る画像としては複製する** ◎。**本人に申告させる仕組みそのもの**だからである |
| **検便条件の出どころ** | **`調理担当ですか？` の申告** ◎（フォームの設問 ◎ ／ 前回データの列（記録） ／ 割り当て時にこの値を見ている ◎） |

**入力の型は 7 項目から 6 項目になった**（調理可否は希望と同じくフォームの回答に乗ってくる）。

**採らなかった案の理由は 6 に 1 段で残した。** B は成立しない ◎（名簿に学籍番号が無く ◎、氏名の入力パターンが多すぎる ◎）、
C は担当者に転記作業を足す、D は Before の目視を残す。**3 つとも「いま無い工程を足す」側である。**

## 影響

- **6「すでにあるもの」の表**の名簿の行の出口を「そのまま入力に取る」→「**入力前提に置かない**」に書き直した
- **6 に「調理担当者名簿を入力前提に置かない」を新設**し、**理由 2 つ**と**採らなかった案 A・B・C・D**を 1 段で置いた
- **6 スコープ内 1** の括弧内から名簿を外し、**6 項目**に直した。調理可否が希望に乗ってくることを 1 行足した
- **4-1 の Before** の「名簿と目で照合する ◎」を、自作サイトの申告列で読む形に直した
- **6「すでにあるもの」の自作サイトの行**を**シフト希望提出履歴サイト 1 本**に名指しで直し（シフト表確認も希望確認画面も同じサイトの別ボタンである ◎ 記録）、
  **割り当て時の「調理／非調理を絞って見る」役割 ◎ はスコープ内 5（生成）が吸収する**ことを書いた（サイトを作り直さない）
- **下流の [`docs/tech-requirements.md`](../../tech-requirements.md) が動いた** — 5-1 から名簿の行が消え（7 種類 → 6 種類）、
  規則 5 が申告で書き直された。**あちらの更新ログはこの ADR を指す**（動いたのは上流の判断 1 つなので、
  `docs/ADR/tech-requirements/` は起こさない）

## 動いていないもの

- **1〜3・5・7 は 1 行も動いていない。** 4-2（入る側の Before = After）も動いていない —
  **フォームの項目も聞かれ方も、貼られている名簿の画像も、そのまま複製する**
- **達成条件 1〜4・スコープ外・△ 1〜8 は 1 つも動いていない。**
  **△ は増えていない** — 申告違いが検出できないのは Before と同じ ◎ であり、発生した記録も無い。**新しい空白ではない**
- **M1〜M6 の完了の定義も日付も動いていない。**
  **M2（違反 0）は、むしろこれで実行できるようになった** — 検便条件の引き先が
  [`data/前回の希望データ-モック.csv`](../../../data/前回の希望データ-モック.csv) の `調理担当ですか？` 列に定まったためである
  （名簿側のモックは存在しない）
- **委員会に何も要求していない** ◎（作る側 19 はスコープ外のまま）
