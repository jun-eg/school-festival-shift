# ADR design-doc-0007: 友達欄を「フォームに残すだけで、誰も読まない」としていたのが崩れた — 担当者が手で寄せる列になり、書式の縛りを外した

- **Status**: 有効
- **Date**: 2026-09-23
- **対象**: `docs/design-doc.md` — 4-2. 入る側（変わらないもの・壊さないことが要件である状態）／ 6. Functional Requirements（「渡らない ◎」資産の表 ／「成果物に含める」を採る ／ スコープ外 ／ スコープ外に置いた仕組みへの依存の確認 ／ 新設「友達欄は担当者が手で寄せる — MVP の外」）／ 7. M1 の完了の定義
- **出典**: [issue #200](https://github.com/jun-eg/school-festival-shift/issues/200) の本文とコメント（2026-09-21 ／ 2026-09-22）／ [`ADR 入る側-0012`](../user-journey-map/入る側-0012-友達欄の指定が守られていないが崩れた.md)

## それまでの結論

6 のスコープ外に、こう書いてあった。

> | 友達欄に乗った期待が捨てられている（理由は「余裕がない ◎」であって書式ではない） | 作る側 6・28 / 入る側 2・3・23 | 友達欄は**フォームの項目としては残す**（聞かれ方を変えないため）が、**割り当ての材料にはしない**。空欄 15/39 ◎ の内訳が △ である以上、主軸に置けない（→ 5. 候補 G） |

> - **フォームの項目・聞かれ方を変えること** — 入る側は Before = After である（→ 4-2）。同じフォームを再現するだけで、内容は変えない

「渡らない ◎」資産の表は、**正規表現バリデーションを 3 箇所（学籍番号・友達欄・希望時間）**として成果物に含めていた。
**友達欄の中身は、生成も担当者も読まない**形だった — フォームで集めて、回答シートに残るだけである。

## 何が起きたか

**issue #200 で、友達欄をどこまで加味するかが決まった**（2026-09-22 のコメント）。

- **加味するのは「担当者に余裕があれば手作業で」の程度でよい。** 生成のロジックには組み込まない
  — 2026-09-21 のコメントで「割り当ての材料にしない」を動かさないと判定したとおりである（期待はあるがペインの証拠が 0 件 ◎ (0/5) ／ 期待した 4 人のうち記録に値があるのは 2 人だけ ◎）
- **ただし手作業の経路は整えておく。** いまは友達欄が回答シートにしか無く、手で寄せようにも**割り当てと並べて見る場所が無い**
- **手作業なので、友達欄にバリデーションは要らない。自由記述でよい**（「太郎君」「同期」「先輩」など）

**書式の縛りを外す根拠は記録の側にある。** 期待を口にした 4 人のうち 2 人（2・3 人目）は空欄で、
答えた「同期の女」「友達の名前」は **10 桁英数字の正規表現が弾く形である** ◎（→ `ADR 入る側-0012`）。
**機械が読まないのなら、学籍番号の形を求める理由が残らない。**

**MVP ではない。** 担当者の手に委ねる上積みで、達成条件にも M1〜M6 の判定にも入れない。

## 新しい結論

**友達欄は、担当者が余裕のあるときに手で寄せるための列である。生成は読まない。**

| | |
| --- | --- |
| **割り当ての材料にするか** | **しない**（動いていない）。生成の入力に友達欄は現れない（→ tech-requirements 5-2） |
| **どこで読むか** | **割り当てのマス目 4 枚の 3 列目**（学籍番号 ／ 氏名 ／ **一緒に組みたいお友達**）。氏名と同じく、**生成のたびに回答から入る表示の列**である。**配る画像には載らない** |
| **どう寄せるか** | **担当者がマス目のセルを書き換える。**既にある手直しの経路（→ tech-requirements 5-3）に乗るので、**生成し直しても残る。**新しい操作を足さない |
| **フォームの書式** | **縛らない。自由記述**（任意項目のまま）。正規表現は**学籍番号と希望時間の 2 箇所**になった |
| **MVP か** | **MVP の外。**達成条件・M1〜M6 の判定は、この列にも書式にも依存しない |

**入る側から見ると、項目は 6 つのまま**（学籍番号／氏名／学年／調理可否／友達欄／希望時間）で、**手数は増えない。**
**動いたのは友達欄の書式の縛りが 1 つ外れたことだけで、縛りが減る向きである** — 学籍番号の確認で止まった 1 人 ◎ (1/5) と、
弾かれる形で答えていた 2 人 ◎ が書けるようになる。**5 が候補 E・I を落とした「入る側のコストで作る側の時間を買う」には当たらない。**

## 影響

- **6 に「友達欄は担当者が手で寄せる — MVP の外」を新設**し、上の表を置いた
- **6 スコープ外**の友達欄の行の但し書きを、「フォームに残すだけ」から「**材料にしない。担当者が手で寄せる列として並べる**」に書き直した
- **6「このドキュメントで追加したスコープ外」**の「フォームの項目・聞かれ方を変えること」に、**友達欄の書式だけは縛らない**ことを例外として書いた
- **6「渡らない ◎」資産の表**と「成果物に含める」の段で、**正規表現を 3 箇所 → 2 箇所**に直し、転記の例外を **2 つ → 3 つ**（締切・日付と営業時間・**友達欄の書式**）にした
- **6「スコープ外に置いた仕組みに、MVP が依存していないことの確認」**の友達欄の行に、マス目に並ぶのは表示だけであることを足した
- **4-2**の「聞かれること」の行と「壊さないことが要件である状態」に、**友達欄の書式の縛りが外れた**ことを足した。**Before = After の読みは動かしていない**（項目・手数・集める口・配る口は同じ）
- **7 の M1 の完了の定義**の「3 箇所の正規表現」を「2 箇所」に直した（定義した時点の数を合わせただけで、判定の中身は動いていない）
- **下流の [`docs/tech-requirements.md`](../../tech-requirements.md) が動いた** — 4-1 の #5 に「成果物では縛らない」を但し書きで足し（**表そのものは記録の転記なので書き換えない**）、5 の #2・#3、5-2 を直した。
  **あちらの更新ログはこの ADR を指す**（動いたのは上流の判断 1 つなので、`docs/ADR/tech-requirements/` は起こさない）
- **実装は [`src/`](../../../src/) が持つ** — `form-definition.js`（友達欄の正規表現を外した）／ `sheet-layout.js`（マス目の名前のある列が 3 つになった）／ `assignment-grid.js` の `friendsFromAnswers`

## 動いていないもの

- **5 の候補 G は消していない**（「候補は消さない」）。**友達欄を生成の選好に使う案は、上積みとしてそのまま残る**
- **達成条件 1〜4・△ 1〜8 は 1 つも動いていない。****△ は増えていない**
- **M1〜M6 の日付は動いていない。**達成条件の判定に友達欄は入っていない
- **tech-requirements 7 のモック化規約（友達欄の参照先の解決）は動いていない** — あれは**前回の記録**（学籍番号で書かれた 24 件 ◎）を
  モックに写すときの規約であって、今年の書式ではない
