# ユーザージャーニーマップ — 学祭シフト作成

> 『ユーザが特定のゴールを達成するまでの一連の体験』を可視化する。

アイデア出しフレームワーク 3 ステップの **1 つ目**。出力（改善機会リスト）が HMW の入力になる。

## 凡例：情報の出典

マップ内の各項目には出典を付ける。**想像で埋めた部分と裏が取れた部分を区別する**ため。

| 記号 | 意味 |
| --- | --- |
| ◎ | 裏が取れている（2026-09-13 の**担当経験者**インタビューで確認） |
| ◎入 | 裏が取れている（2026-09-13 の**シフトに入る側**インタビューで確認。現在 2 人） |
| ○ | 伝聞・本人の推測（直接は観測していないが、証言としては出ている） |
| △ | 未検証（想像のまま。まだ誰にも確かめられていない） |

◎ と ◎入 を分けているのは、**作る側 1 人の証言と入る側の証言が混ざると、どちらの視点の裏付けなのか分からなくなる**ため。

◎入 の項目には、**入る側 2 人のうち何人が言ったか**を (2/2)(1/2) で添える。1 人だけの話を 2 人分の裏付けに見せないため。

### 作る側の証言を一般化するときの注意

**証言者は技術力が高い側の外れ値**である ◎。担当は**毎年 1 人が持ち回りで、幹部のこともメンバーのこともある** ◎ ため、
年によって担当者のスキルは大きく変わる。証言者は Google フォームに正規表現バリデーションを設定し、
スプレッドシートと紐づけ、スクリプトでデータを整備した ◎ が、**例年はそこまでやらない** ◎。
実際、前々年度は手でエクセルに転記していた ○。

さらに証言者は、シフト表を JSON で管理して **Vercel に確認サイトを自作** している ◎。
これも例年のやり方ではない ◎（引き継がれたやり方は LINE ノートに画像を貼るだけ ◎）。

→ 証言者の年に「軽かった」工程が、**例年も軽いとは限らない**。該当箇所には注記を入れてある。
→ 逆に、証言者が自作したもの（フォームのバリデーション／整備スクリプト／確認サイト）は
　 **どれも翌年に渡らない** ◎。「すでに試したこと」の節に、効いたもの・効かなかったものを整理してある。

### 入る側 1 人目（風蔵）を一般化するときの注意

**風蔵も外れ値側である。** 去年の学祭当時は幹部で、調理可だったため、

- 希望時間は「**幹部なのでほぼ全部**」で出しており ◎入、**予定を見比べて希望を絞る作業をしていない**
- シフト量を**他人と比べていない** ◎入（「幹部でずっといたので何とも」）

つまり**当時の立場が「どうせ大学に居る」側で、制約が薄く、比較もしない層**の証言である。
しかも作る側の証言者と**同学年・当時同じ幹部・どちらも調理可**で、属性がほぼ完全に重なっている。
issue #13 が散らそうとした軸（非調理／1・2 年／締切後提出／事後申告）は、この時点で**まだ 1 つも埋まっていない**。

→ この 1 人で「入る側はこうだ」と決めない。**否定に見えるものは「縮小」までに留める。**

### 入る側 2 人目（きた）を一般化するときの注意

**きたも「全部空いている」側である。**

- 希望時間は「**最初から全日程空けてたから希望全部出した**」◎入 → 1 人目と同じく、**予定を見比べて希望を絞る作業をしていない**
- そのため**希望と違うコマに入りようがなく** ◎入、事後申告の体験も取れない

一方で、去年の学祭当時は **2 年生・幹部ではない**（幹部の手伝いはしていた）◎入 ため、
issue #13 の軸のうち **1・2 年**が 1 人だけ埋まった。**比較の証言（回答 9）が初めて取れたのもこの人**である。

→ 入る側 2 人は**どちらも調理可・どちらも全日程 OK**。
　**非調理**・**日程に制約がある人**・**締切を過ぎて出した人（5 人）**・**事後申告した人（1〜2 人）**は依然として空白。
→ 「希望がどれだけ通るか」「希望と違ったときどうするか」は、**2 人とも構造的に答えられない立場**にある。
→ 2 人目にも**追い質問をしていない**（1 往復のみ）。回答 5・7・10 には follow-up が要る。

## ペルソナ

| 項目 | 内容 |
| --- | --- |
| **名前** | 佐藤 みなみ（仮名）△ |
| **属性・所属** | 大学 3 年。サークルの模擬店でシフト作成を任された 1 人 ◎。実行委員ではない ◎ |
| **ゴール** | 4 日間の模擬店を、各 30 分枠に必要な役割・人数が埋まった状態で回しきる ◎ |
| **前提知識・スキル** | **年によって大きく振れる** ◎。Google フォーム／スプレッドシートは触れる ◎。<br>バリデーションやスクリプトまで書ける年もあれば、手でエクセルに転記する年もある ◎○ |
| **置かれている制約** | ・メンバーは 20〜30 人、期間は 4 日間（11/1〜11/4）◎<br>・**担当は毎年入れ替わる** ◎。押し付け、または幹部の持ち回りで決まる ◎<br>・**引き継がれるのは前年のシフト表 1 枚と、LINE の短い説明だけ** ◎<br>・**自分もシフトに入る当事者** ◎。証言者は調理と準備／片付けも兼任 ◎<br>・**学祭運営委員会の外部ルールに縛られる** ◎（下記）<br>・**無報酬** ◎<br>・確定後の欠席・交代が起きる ◎（4 日間で 5 件以下 ◎） |

### 立場を 1 人に絞った理由

「シフトを作る人」と「シフトに入る人」で体験が分かれるが、**このペルソナは両方を兼ねている** ◎。
マップの視点は **「作る人」としての体験**に固定する。

> **当初の想定は否定された。** 「作る側なので自分の希望を後回しにする」という体験は**無かった** ◎。
> 入る時間が多かったのは事実だが、理由は「幹部でどうせ大学に居るから」であり、シフト作成担当だからではない ◎。
> 担当者の負担は**割り当ての不利ではなく、無報酬の作業量そのもの**に出ている ◎。

| **調理責任者** | 各調理枠に 3・4 年生を 1 人以上、調理責任者として置く ◎ | 同上（口頭・前年度担当者経由）◎ |
| **クリーンパトロール** | 委員会が指定した時間に、指定された人数を出す ◎ | **フォーム作成の後**に提示される ◎ |

| 10 | 一番面倒だったところ／困っていないところ | **クリーンパトロールをサボる人がいて代わりに行ってる人がいた → 絶対サボらなさそうな人とペアにした方がいい。みんな意外と時間通りに来ないから余裕もっといた方がいい** | 面倒だった点は挙がらず、代わりに**当日運用の穴が 2 つ**出た ◎入。①**連絡なしのサボりと肩代わり**（作る側は未認知）②**遅刻が常態で、枠に余裕が無い**。1 人目の「提出がだるい」は**繰り返されなかった** |

**この 1 人から言えること**: 入る側の関心は**当日の回り方**にもある ◎入。
シフト表の作り（見やすさ・控え）ではなく、**その枠が実際に実行されるか**の方が具体的な要望として出てきた。
なお 2 人目は「一番面倒だったところ」を聞かれて**面倒を答えず、改善案を答えている** → 面倒さの実感は薄い可能性 △。

**この 1 人でも言えないこと**: 希望確認画面の核心 2 問（なぜ好評だったのか／全員分が見えるのがなぜ嫌だったのか）。
**2 人目も画面を使っていない**ため、issue #13 の核心は**依然として空白**。

### ここから読み取れること

- **作ったのに使われない**という失敗が実際に起きている ◎。既存の導線（LINE ノートの画像）より手間が増えると選ばれない
  - ただし入る側 2 人目は**サイトを選んでいる** ◎入 → 「全く使われない」ではなく**割れる**。「既存導線と並べると多数は画像に流れる」程度に留める
- **「唯一評価されたのは自分の希望の控え」は取り下げる。** 「好評」の出所は**本人の感覚**であり ○、入る側 2 人は**どちらも使っていない** ◎入 (2/2)
  - ただし**開いた人は複数いる** ◎（「全員分見れちゃうんだ」と言えた人たち）。**使われなかったのではなく、評価が分からない**
  - → 自作した 3 つ（確認サイト・希望確認画面・整備スクリプト）のうち、**入る側に届いたことが確認できているものは無い**。
    確実に効いたのは**担当者自身の作業を軽くしたもの**（学籍番号キー・整備スクリプト・JSON のリアルタイム表示）だけ ◎
  - → **入る側に向けて作るものは、需要の有無から確認する。** 作る側の感覚を根拠にすると同じ失敗を繰り返す
- 割り当てを「見える化」しても時間は縮まなかった ◎。**縮めるには制約チェックと偏り計算を人間から外す**必要がある

## 証言された「理想の状態」

インタビューで**そのまま語られた**理想のフロー ◎。HMW と Design Doc の User Story の一次情報になる。

```
LINE にアンケート URL を貼る
  ↓
「シフト作成」ボタンを押す
  ↓
仮完成
  ↓
ちまちま手で少し修正（5〜15 分）
  ↓
完成
  ↓
LINE に流す
  ↓
修正依頼が来る
  ↓
手で修正（5〜15 分）
  ↓
LINE のノートを差し替える
```

読み取れること:

- **全自動は求められていない。** 「仮完成 → 手で微修正」が前提に入っている ◎
- 許容できる手作業は **5〜15 分**。現状の **3〜6 時間**との差が、解くべき距離 ◎
- 修正ループ（流す → 依頼が来る → 直す）も**同じ 5〜15 分**で回ることが期待されている ◎
- 出入口は **LINE** のまま ◎。置き換え対象は**割り当ての中身だけ**
  - これは「すでに試したこと」とも整合する。**LINE の外に出した確認サイトは使われなかった** ◎
- 修正の反映が「LINE のノートを差し替える」で終わっている ◎。現状の commit → push → PR → merge（10 分）はこの理想に含まれていない

## 確定した改善機会リスト

HMW（次工程）の入力。**解決策ではなく「機会」**として書いている。

### 確定（◎：インタビューで裏が取れた）

**最優先 — 割り当て**

1. 割り当てが全工程で唯一かつ最大のボトルネックになっている（3〜6 時間／3 日がかり／やり直し 20 回規模）
2. 「検便 × 学年（3・4 年）× 時間が合う」の 3 条件で調理系の候補が枯れ、**公平性を犠牲にしてでも同じ人を入れている**
3. 準備・片付けの割り当てルール（午前に仕事→準備／午後に仕事→片付け／両方ある人は片方／どちらも無い人は入れない／複数日で準備が同じ人に偏らないようにする）が複雑で、担当者の頭の中にしかない
4. 「公平」の基準（準備の回数・シフト回数・合計時間）が担当者の頭の中にあり、確かめる手段が目視しかない
5. 粗い単位で集めた希望を 30 分枠に割り直す変換が、担当者の頭の中でしか行われていない
6. 集めたのに使われない希望（「一緒に組めたら嬉しい友達」）がある。入る側 1 人目は**何も書いていない**が、2 人目は「**書けば割と優遇してくれるかな**」と思って書いている ◎入 → **捨てられていることを出す側は知らない**。しかも書き方が「同期の女」という**属性で、個人が特定できない** ◎入 → 使う気になっても、集まっている形では使えない
7. 修正のたびに、初回と同じ制約チェック（検便・学年・時間）を手でやり直している
8. 割り当ての実体は **JSON の手編集**であり、支援は「表として見える」ところまでしかない。制約チェックも偏りの計算も人間に残っている
9. **見える化だけでは時間は縮まなかった**（JSON ＋ リアルタイム表示を作っても 3〜6 時間のまま）

**共有・確認**

10. LINE ノートに画像と URL を並べたときに**どちらが見られるかは割れる** ◎入（1 人目＝画像を拡大／2 人目＝サイトで一気に）。作る側は「サイトは使われなかった」と受け取っているが、**使った人がいたことが担当者に届いていない**。選び分けの理由は 2 人とも未取得 △
11. フォームにログインを付けていないため、**提出した本人の手元に希望の控えが残らない** ◎（事実）。ただし**それで困っている人はまだ 1 人も確認できていない**。入る側 2 人は控えが無くて困っておらず確認画面も未使用 ◎入 (2/2)、根拠だった「好評」も**本人の感覚** ○ → **需要の有無から聞き直す対象**
12. **全員分が見えることには反応が出ている** ◎。複数人が「**全員分見れちゃうんだ**」と作る側に直接言っている。
　　ただし「評判が悪かった」は本人も**言い過ぎ**と認めており ○、**拒否感なのか驚きなのかは未検証** △ →
　　**「本人の分だけ見える必要がある」と決め打ちしない**。まず反応の中身を聞く
　　→ **そう言えた時点で確認画面を開いている** ◎。入る側 2 人（未使用）では取れなかった核心は、**この人たちにしか聞けない**
13. 生データ（スプレッドシート）をそのまま共有する道は、重複行とスマホ非対応で塞がっている
14. 1 件の変更を反映するのに commit / push / PR / merge が必要で、1 回 10 分かかる

**引き継ぎ**

15. 担当が毎年入れ替わるのに、渡るのは**前年のシフト表 1 枚と LINE の一文**だけ
16. 作り込んだもの（フォームのバリデーション・整備スクリプト・JSON・確認サイト）が**翌年に一切残らない**（「整ったデータの集まるフォームは引き継げない」）
17. 各工程の重さが、**その年の担当者の技術力だけで決まってしまう**
18. 必要人数の根拠が「去年と同じ」しかなく、妥当性の検証も翌年への引き渡しもできない
19. 委員会のルール（検便・学年・クリーンパトロール）が文書化されず人伝いに渡っている

**順序・タイミング**

20. クリーンパトロールの枠が**フォーム作成後**に確定するため、枠設計が後から崩れる
21. 日ごと・年度ごとに営業時刻が変わるため、前年の成果物を再利用できない
22. 未提出者を特定しないまま割り当てが始まり、後から申告（締切後提出 5 人・流した後の指摘 1〜2 人）が来て組み直しになる

**担当者の立場**

23. 担当者が無報酬で、模擬店の他の役割（調理・準備・片付け）と兼任している

**入る側（◎入：2 人。どちらも調理可・全日程 OK で属性が偏っているので要追加検証。(2/2) は 2 人が揃った項目、(1/2) は片方だけ）**

24. 入る側の提出は**スマホのスキマ時間**で行われている ◎入 (2/2)（締切直前／電車の中）→ 腰を据えて入力される前提は置けない。ただし「**一番面倒なのは提出**」と言ったのは 1 人目だけ ◎入 (1/2) で、2 人目は詰まりも面倒も挙げていない → **摩擦の大きさは人によって振れる**
25. 自分の出番の確認は**配布直後・前日・当日**に立つ ◎入（1 人目＝前日 1 回／2 人目＝3 回。**前日は共通**）。**当日も参照される**ため、差し替えは当日分まで届く必要がある。探し方は画像の拡大／サイトの一覧に割れ、**どちらも不満としては挙がっていない** ◎入
26. 希望と違うコマに入っていても「**言いづらい**」と感じられている ◎入 (1/2)（1 人目の想定。**2 人とも実体験は無い**）
27. **クリーンパトロールをサボる人がいて、その場に居た別の人が代わりに行っている** ◎入 (1/2、2 人目が目撃)。作る側も**認識していたが、その場で対応できたため覚えていない** ○ → **見えていない穴ではなく、その場で解消されて記録に残らない穴**。担当者側の優先度は低い
　ただし**肩代わりは入る側から見えている** ◎入 → 担当者の視界では解消済みでも、**入る側には不公平として残る**。委員会指定枠に「**その枠が実際に実行されるか**」という条件を入れる余地はある
28. **みんな意外と時間通りに来ない** ◎入 (1/2) → 30 分ぴったりで刻んだ枠に余裕が無く、遅刻がそのまま次の枠に乗る。これも作る側は**認識のうえで当日吸収している** ○ ため、担当者側の優先度は低い
29. 入る側の体感の重さは**シフト表に載らない仕事**（朝からの幹部手伝い）で決まっており、**シフト時間を均しただけでは公平感に届かない** ◎入 (1/2)。割り当ての量そのものには不公平感は出ていない ◎入
