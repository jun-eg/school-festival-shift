# E2E が実機で止まるときの要約 — 症状・切り分け・対処

`npm run e2e` が止まる 3 つの事象と、すでに見ている 1 つを、症状から引けるようにまとめた。
3 つは実機で起こしておらず、人が「確かめずに受け入れる」と決めた（2026-10-25）。文言には、コードから引いたものと、Google 側の返事の推測が混ざる。推測は原本が区別している。

## A. clasp のトークンが 7 日で切れる

- 仕組み: OAuth 同意画面が「テスト」の間、リフレッシュトークンは 7 日で失効する。
- 症状: 出力の最初の API 呼び出しで `access token が取れない: invalid_grant（…）。clasp login をやり直す`。何も書かずに止まる。
- 対処: 人が `clasp login --creds …`（[`e2e/README.md`](../e2e/README.md) の用意するもの 3）をやり直す。承認はブラウザなので Claude にはできない。やり直せば無人に戻るはずだが、失効した状態からは見ていない。

## B. スクリプトと GCP プロジェクトの結び付けが外れる

- 仕組み: `scripts.run` は、呼ぶ側のクライアントとスクリプトが同じ GCP プロジェクトでないと通らない。`.env` の GCP プロジェクトの欄はコードが使っていないので、事前には見つからない。
- 症状: push までは通り、最初の `buildTemplate` が `buildTemplate が失敗した（HTTP <status>）: <本文>` で落ちて、再試行されない。status は 403 か 404 のはずだが推測で、本文も実機で見ていない。
- 切り分け: トークンが生きている（A でない）ことを見て、エディタの「プロジェクトの設定」の GCP プロジェクト番号を見る。
- 対処: 人がエディタで番号を入れ直す（用意するもの 2）。そのあと Claude が `npm run e2e` を回して通ることを見る。

## C. 呼び出しが 180 秒で切れる

- 仕組み: Node は 180 秒で待つのをやめ、5 秒後に 1 回だけ再試行する。Apps Script 側の実行は止まらず、最大 6 分続くので、1 回目と 2 回目が重なりうる。実機の所要時間は数秒から数十秒で、切れたことは一度も無い。
- 二重に走っても困らない: `buildTemplate`（足りないものだけ足す冪等な作り）と `e2eGenerate`（同じ入力から同じ案を書き直す）。
- 困る: `createFormFromPicker`。順に 2 回なら 2 回目は「もうフォームがあります」で止まるが、途中で落ちた後や重なったときは、フォームが 2 つできて孤児が残りうる。
- 形は同じだが結果が変わる: `e2eClearForNextYear`。2 回目は外したフォームの URL が空で返り、e2e の検査は落ちる。フォームは控えから次の回の頭で捨てられる。
- 症状: 最後の例外は Node の中断（推測: `The operation was aborted due to timeout`）か `<関数名> が失敗した（HTTP <status>）: <本文>`。切り分けはエディタの「実行数」で同じ関数が 2 本あるかを見る。
- 対処: 冪等なものは `npm run e2e` を回し直す。フォームの孤児は次の回の頭で拾う。拾えないものは人がドライブで題名から探してゴミ箱へ移す。

## D. 初回だけ `reading from storage … NOT_FOUND`（実機で見た）

push 直後の最初の呼び出しだけ返り、5 秒後の 1 回の再試行で通る。止まらないので何もしない。2 回目も出るなら push 先か B を疑う。

## 開いていること

7 日で切れること・再ログインで戻ること・B の status と本文・180 秒で切れたときの重なりの振る舞いは、どれも実機で起こしていない。起こしたら原本の推測を置き換える。

詳しくは [原本](agent/e2e-症状と対処.md)。
