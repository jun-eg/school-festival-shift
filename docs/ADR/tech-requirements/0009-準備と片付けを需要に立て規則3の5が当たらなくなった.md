# ADR 0009: 「`準備`・`片付け` は需要に立てない」が、準備日・片付け日を丸ごと空にした

- **Status**: 有効
- **Date**: 2026-09-22
- **対象**: [`docs/tech-requirements.md`](../../tech-requirements.md) — 3 の規則 3（⑤ と「規則 3 が乗る先」）／ 5-1 の #2 ／ 5-4 ／ 5-5 ／ 6 の #2・#3 の理由 ② ／ [`scripts/M2の宣言.json`](../../../scripts/M2の宣言.json) ／ [`scripts/生成の所要時間の宣言.json`](../../../scripts/生成の所要時間の宣言.json)
- **出典**: [issue #210](https://github.com/jun-eg/school-festival-shift/issues/210) の続き ／ [`data/`](../../../data/) の前回の確定シフトのモック 4 本（171 行）／ 実機に書き戻して見えたこと（→ [`src/real-device-log.md`](../../../src/real-device-log.md)）

## それまでの結論

**[`tech-requirements/0008`](0008-時間帯を空けた需要が効くのは全枠ではなくその日の調理帯になった.md) がこう決めていた。**

> **`準備`・`片付け` は需要に立てない側に倒した。** **規則 3 が違反の側で担保しているからである。**
> **立てる側に倒すには人数の出どころが要るが、記録にあるのは「置かれた人数」であって「要る人数」ではなく、上流にも無い。**

**5-1 の #2 には、その帰結として但し書きが付いていた** —
「**`準備`・`片付け` の需要を空欄で書くと調理帯に立つ。書くなら時間帯を明示する**」。
**時間帯を空けた行が効く先は、役割によらず「その日の調理帯」だった。**

## 何が起きたか

**判定した案を実機の生成シートに書き戻したら、準備日と片付け日が丸ごと空だった。**
**割り当て 300 行は `2025-11-02` に 143 ／ `2025-11-03` に 157 で、`2025-11-01` と `2025-11-04` は 0 行である。**

**原因は 2 つ重なっている。**

1. **その 2 日は調理帯が 0 枠なので、店の 5 役割の需要が立たない**（0008 の決めそのもの。これは正しい）
2. **規則 3 が `準備`・`片付け` を置くのは「その日に置かれた人」についてだけ**なので、誰も置かれない日には 1 行も出ない

**違反にも未充足にもならない。** **需要が無いので未充足は数えようがなく、誰も置いていないので規則 3 も破れない。**
**M2 は違反 0 件・名指しされていない未充足 0 件で合格したまま、1 日ぶんの人が消えていた。**

**記録はそうなっていない。** **[`data/`](../../../data/) の 171 行を数え直すと、こうである。**

| 日 | `準備` | `片付け` | 店の 5 役割 |
| --- | --- | --- | --- |
| **2025-11-01**（準備日） | **25 人**（枠ごと 5〜22 人・中央 16） | 0 | **0 行** |
| **2025-11-02** | 8 人（`08:00`-`10:00`。枠ごと 8 人） | 15 人（`18:00`-`20:00`） | あり |
| **2025-11-03** | 8 人（同上） | 26 人（枠ごと 23〜26 人） | あり |
| **2025-11-04**（片付け日） | **11 人**（枠ごと 8〜10 人・中央 9） | 0 | **0 行** |

**`2025-11-01` は `準備` が 25 人で、店の役割が 1 行も無い。**
**この日を規則 3 の ①〜⑤ で作ることはできない** — **① が見るのは「その人のその日の割り当て」で、
そのとき `準備`・`片付け` の行そのものは見ない**ので、**この 25 人はどう見ても ⑤「どちらも無い」に落ちる。**

**規則 3 は、店の役割に就いた人に `準備`・`片付け` を乗せる規則だった。**
**準備日・片付け日には乗せる先が無い。****規則が足りなかったのであって、記録が規則を破っていたのではない。**

## 新しい結論

**`準備`・`片付け` も需要に立てる。** **3 つが動いた。**

| | 動いたこと |
| --- | --- |
| **空欄の時間帯の読み**（5-1 の #2） | **「その日の調理帯」から「その役割の帯」になった** — **`準備` → `準備開始`〜`調理開始` ／ `片付け` → `片付け開始`〜`片付け終了` ／ それ以外 → `調理開始`〜`調理終了`。**<br>**0008 の但し書き（空欄で書くと調理帯に立つ。書くなら時間帯を明示する）は要らなくなった。**<br>**担当者は日も時間帯も書かずに 1 行ずつ書ける** — **日ごとの 5 時刻を需要の側にもう一度書かせない**（→ 5-1 の #1） |
| **埋める段**（5-5） | **4 段目が増えた** — **規則 3 を満たした後に、まだ足りていない `準備`・`片付け` の枠を帯の中で埋める。**<br>**1 段目（きつい順）に混ぜない** — **その人のその日の店の割り当てがまだ決まっていないうちに帯へ置くと、②〜④ が壊れる。**<br>**4 段目で置くのは「同じ帯にもう 1 枠足す」か「その日に店の役割へ就いていない人を置く」かのどちらかだけになる** |
| **規則 3 の ⑤**（3 ／ 5-4） | **当たらなくなった。**<br>**午前・午後は店の役割の行からしか立たない**ので、**「どちらも無い」＝「その日に店の役割へ就いていない」**である。<br>**`準備`・`片付け` が需要になったいま、その日に `準備` だけ置かれている人は、置かれたことそのものが仕事である。**<br>**①〜④ は 1 つも動いていない。****M2 の「違反 0 件」から ⑤ が抜けた** |

**人数の出どころは入力である。** **ここが値を決めない** — **記録にあるのは「置かれた人数」であって「要る人数」ではない。**
**#2 は毎回入力するもの**なので、**担当者が日ごとに書く。**
**判定に使う値の置き方だけを [`scripts/M2の宣言.json`](../../../scripts/M2の宣言.json) が持つ**
（**記録の日ごとの中央値**。`2025-11-01` `準備` 16 ／ `2025-11-02` `準備` 8・`片付け` 15 ／ `2025-11-03` `準備` 8・`片付け` 26 ／ `2025-11-04` `準備` 9）。

**動かしていないもの。** **型（`(日・時間帯・役割名・人数)`）／切り方（重なる枠すべて・最大まで引き上げる・足し合わせない）／
日の欄の読み／枠 88（26/24/24/14）／店の 5 役割の人数 ◎／規則 3 の ①〜④／規則 1・2・4・5・6／M2 の合格の線の文言。**

## 影響

**本文。**

- **3 の規則 3** … ⑤ に「当たらなくなった」を付け、**「規則 3 が乗る先」の節を新しく置いた**（何に乗る規則か・なぜ準備日に当たらないか・⑤ が指していた形がなぜ違反でなくなったか）
- **5-1 の #2** … 型の欄を「その役割の帯」に直し、**0008 の但し書きを外した。**「`準備`・`片付け` は需要に立てない」の段を**立てる側に書き直し**、人数の出どころが入力であることを足した
- **5-4** … 違反の行を **①〜⑤ → ①〜④** に直し、**⑤ が入らない理由（⑥ と違って上流待ちではない）**を足した
- **5-5** … 「埋める順」に**準備・片付けが入らない理由**を、「準備・片付けをどこに置くか」に**3 段目と 4 段目**を足した。却下した形に**「1 段目に混ぜる」**を 1 行足した
- **6 の #3 の理由 ②** … 規模を **延べ 268 → 1038**（店 256 ＋ 準備・片付け 770 ＋ 指定枠 12）。**6 の #2** の走査の量も揃えた

**実装。**

- **帯の定義**（`prepCleanupBands` ／ `prepCleanupRoles` ／ `isInBand`）**を [`src/generate.js`](../../../src/generate.js) から [`src/count-violations.js`](../../../src/count-violations.js) へ移した** — **数える側（[`src/name-unmet.js`](../../../src/name-unmet.js)）も同じものを読むようになったので、規則の側に 1 つだけ置く**
- **`needCovers` の空欄の読みが役割ごとになった**（→ `blankBandFor`）
- **`generate` に 4 段目が増えた**（`prepCleanupUnits` ／ `fillPrepCleanupDemand`）。**1 人が同じ日の両方の帯に入らない見張り**（`prepCleanupNotBothBands`）も足した
- **`prepCleanupDetail` の ⑤ が違反を返さなくなった**

**判定。** **M2 は合格の線を 2 つとも保った** — **違反 0 件・名指しされていない未充足 0 件・超過 0 枠。**
**割り当ては 300 行 → 826 行**（`2025-11-01` **0 → 342** ／ `2025-11-02` 143 → 176 ／ `2025-11-03` 157 → 220 ／ `2025-11-04` **0 → 88**）。
**`準備` は 13 件 → 482 件、`片付け` は 21 件 → 78 件。**
**需要のべ 1038 ＝ 置いた 826 ＋ あと何人 212** で揃い、**未充足は 2 件・あと 2 人 → 48 件・あと 212 人**になった
（**未充足そのものは線を当てる相手ではない** → 5-4）。
