# ADR 0008: 「日と時間帯を空けた行は全枠に効く」が、営業していない帯にまで店の需要を立てていた

- **Status**: 有効
- **Date**: 2026-09-22
- **対象**: [`docs/tech-requirements.md`](../../tech-requirements.md) — 5-1 の #2 ／ 5-4「未充足は、枠と役割ごとに 1 件である」／ 6 の #2・#3 の理由 ② ／ [`scripts/M2の宣言.json`](../../../scripts/M2の宣言.json) ／ [`scripts/生成の所要時間の宣言.json`](../../../scripts/生成の所要時間の宣言.json)
- **出典**: [issue #210](https://github.com/jun-eg/school-festival-shift/issues/210) ／ [`data/`](../../../data/) の前回の確定シフトのモック 4 本（171 行）

## それまでの結論

**5-1 の #2 はこう書いていた。**

> **(日・時間帯・役割名・人数) の行の集合。****日と時間帯を空けた行は、全枠に効く**（前回の値 ◎ はこの形で 1 組書ける）

**5-4 の「需要の切り方」も同じ言葉を持っていた**（「**日と時間帯を空けた行は全枠に効く**」）。
**判定入力の必要人数は、この読みに合わせて 5 行とも日も時間帯も空欄だった**
（[`scripts/M2の宣言.json`](../../../scripts/M2の宣言.json)）。
**88 枠 × 1 枠 8 人 ◎ で、需要のべは 704 である**（→ 6 の #3 の理由 ②）。

## 何が起きたか

**必要人数の行が時間の次元を持っていなかったので、営業していない帯にも店の 5 役割の需要が立っていた。**

**[`tech-requirements/0007`](0007-前回の5時刻を確定シフトから算出しM2の判定入力に入れた.md) で 5 時刻が日ごとの値になり、
準備日・片付け日の調理帯が 0 枠であることが入力の側に出た。**
**それでも需要は全 88 枠に立つので、`2025-11-01`（準備日）の `08:00-08:30` に `呼び込み` 2 人・`列整理` 2 人の未充足が出る。**
**店を開けていない日の朝 8 時に、呼び込みと列整理が要ることになっていた**（→ [issue #210](https://github.com/jun-eg/school-festival-shift/issues/210)）。
**埋まる側も同じである** — **準備日に `呼び込み` の需要があれば、その日を希望した人はそこに置かれる。**

**逆向きの穴もあった。** **`準備` と `片付け` には需要の行が 1 つも無い**（5 役割 ◎ に入っていない）ので、
**未充足の側では一度も数えられない。** **担保しているのは違反の側（規則 3）だけである。**

**型の欠陥ではない。** **5-1 の #2 は `(日・時間帯・役割名・人数)` を持っていて、書けるのに空欄で置いていただけである。**

**記録が裏付けた。** **[`data/`](../../../data/) の 171 行で、店の 5 役割（`調理責任者`／`調理`／`会計`／`呼び込み`／`列整理`）が
現れるのは `2025-11-02` と `2025-11-03` の `10:00`〜`18:00` だけで、準備日にも片付け日にも 1 行も無い。**
**これは確定シフトから算出した `調理開始 10:00`／`調理終了 18:00`（→ 7）と両端とも同じである** —
**別々に出した 2 つ（帯の側と需要の側）が同じ線に乗った。**

## 新しい結論

**5-1 の #2 は、いまこう書いている。**

> **(日・時間帯・役割名・人数) の行の集合。****日を空けた行は全日に、時間帯を空けた行はその日の `調理開始`〜`調理終了` の帯に効く**
> **「全枠」ではない** — **営業していない帯にまで店の役割の需要が立つ**（準備日の朝に `呼び込み` が要ることになる）。
> **帯の側で決まるので、準備日・片付け日は調理帯が 0 枠であり、日ごとに書き分けなくても需要が立たない。**
> **但し、`準備`・`片付け` の需要を空欄で書くと調理帯に立つ** — **その 2 つは調理帯の外にある帯なので、意図した所に立たない。****書くなら時間帯を明示する**

**動かしていないものを先に並べる。**

| | |
| --- | --- |
| **型** | **`(日・時間帯・役割名・人数)` のまま**（→ 5-1 の #2・#4）。**#2 と #4 が同じ形式であることも動かない** |
| **人数 ◎** | **調理責任者 1・調理 2・会計 1・呼び込み 2・列整理 2 のまま**（上流 6「すでにあるもの」） |
| **切り方** | **重なる 30 分枠すべて ／ 最大まで引き上げる ／ 足し合わせない**（→ 5-4）。**空けた行と書いた行で切り方は変わらない** — 変わるのはどの区間に当てるかだけである |
| **日の欄** | **空欄なら全日に効く。**準備日・片付け日に立たないのは日の欄ではなく帯の側で決まる |
| **判定入力の行数** | **5 行のまま**（日も時間帯も空欄）。**担当者が毎年書く量は増えない** |
| **枠** | **88（26/24/24/14）のまま。**需要が動いても枠は動かない |

**時間帯の値は 5-1 の #1 の 5 時刻から出る。需要の側で別に持たない** —
**同じ値を 2 か所に書かせると、食い違ったときにどちらが正かが決まらない。**

**`準備`・`片付け` は需要に立てない側に倒した。** **規則 3 が違反の側で担保しているからである。**
**立てる側に倒すには人数の出どころが要るが、記録にあるのは「置かれた人数」であって「要る人数」ではなく、上流にも無い。**

**委員会の指定枠を判定入力に入れた。** **`2025-11-02 16:00-17:00` と `2025-11-03 12:00-12:40` の `クリーンパトロール` 各 3 人である。**
**作り話ではない** — **記録から読める ◎。****時刻は 2 つの形で残っているが、採るのは終了時刻を持っているほうの実体の区間（`start`・`end`）である**
（委員会の指定時刻 ◎ は `slotId` の `2025-11-02T16:10` ／ `2025-11-03T12:10` で、**開始時刻しか残っていない**）。
**どちらを採っても重なる枠は同じ 2 枠なので、判定はこの選び方で動かない。**
**この 2 行が、3 の境界値の「30 分枠の境目に乗らない指定枠」を初めて通す** — **`12:00`-`12:40` が `12:00` と `12:30` の 2 枠に効く。**

## 影響

**本文。**

- **5-1 の #2** の型の欄を書き直し、**但し書き（`準備`・`片付け` を空欄で書くと調理帯に立つ）を足した**
- **5-1 の「#2 と #4 を同じ形式にした理由」**の後ろに、**根拠が「置かれた時間帯」の側であること**（算出であって宣言ではない）と、
  **`準備`・`片付け` を需要に立てない決めと理由**を足した
- **5-4 の「需要の切り方」**を同じ言葉に揃え、**「引き上げる」の段の例（全枠に効く 1 行）を「その日の調理帯に効く 1 行」に言い換えた**
  （**引き上げの向きそのものは動かない**）
- **6 の #3 の理由 ②** の規模を **延べ 704 → 268**（店の 5 役割 256 ＋ 指定枠 12）にした。**6 の #2 の実装上の注意**の走査の量も同じ数に揃えた

**実装。** **判定の中身は 1 つのままである** — **生成も未充足の側も、[`src/name-unmet.js`](../../../src/name-unmet.js) の `requiredAt` という同じ口を通る。**

- **`needCovers` と `requiredAt` が、日付の文字列ではなく日そのものを受ける**（`cookStart`・`cookEnd` が要る）。**触った呼び出しは 6 箇所**
  （[`src/name-unmet.js`](../../../src/name-unmet.js) の 3 ／ [`src/generate.js`](../../../src/generate.js) の 2 ／ [`scripts/M2の判定.mjs`](../../../scripts/M2の判定.mjs) の 1）
- **どの枠にも重ならない需要で止まる口**（`checkEveryNeedLands`）**に、「時間帯を空けた行なのに効く日の調理帯が 1 つも立っていない」が加わった**
- **担当者が読む注記を揃えた** — [`src/sheet-layout.js`](../../../src/sheet-layout.js) の区画 ／ [`src/input-types.js`](../../../src/input-types.js) の `toNeeds` ／
  [`src/name-unmet.js`](../../../src/name-unmet.js) の `unmetSources`

**判定。** **M2 は合格の線を 2 つとも保った** — **違反 0 件・名指しされていない未充足 0 件・超過 0 枠。**
**未充足は 59 件・あと 73 人 → 2 件・あと 2 人**になり、**需要のべ 268 ＝ 置いた 266 ＋ あと何人 2** で揃った。
**割り当ては 681 行 → 300 行**である（**需要が 704 から 268 に下がったのだから、置く先も下がる**）。
**`クリーンパトロール` が 12 件出た** — **規則 6 がこの経路で初めて試された。**
