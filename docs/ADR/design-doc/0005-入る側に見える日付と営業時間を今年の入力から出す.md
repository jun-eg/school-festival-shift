# ADR design-doc-0005: 6 の「フォーム定義は転記である。変える判断をしない」に例外が立った — 入る側に見える日付と営業時間は、今年の入力から出す

- **Status**: 有効
- **Date**: 2026-09-21
- **対象**: `docs/design-doc.md` — 4-2. User Story（入る側の「変わらないもの」）／ 6. Functional Requirements（「『渡らない ◎』資産をどう外したか」／ 新設「入る側に見える日付と営業時間は、今年の入力から出す」／ スコープ内「作るもの」2）
- **出典**: [issue #190](https://github.com/jun-eg/school-festival-shift/issues/190) と、そのコメント（2026-09-21。**担当者の決め**）／ 前回のフォームの質問項目データ（issue #97。→ [`docs/tech-requirements.md`](../../tech-requirements.md) 4-1・4-2）

## それまでの結論

6 の「『渡らない ◎』資産をどう外したか」に、こう書いてあった。

> - **聞き方は前回のフォームの質問項目から転記する。変える判断をしない** — 聞かれ方を変えることは
>   スコープ外に置いてあり（→ 下記）、入る側の Before = After（→ 4-2）はここで守られる

**例外として名指しされていたのは締切 1 つだけ**である（→ [`design-doc/0002`](0002-締切の根拠が逆算から今回の決めに変わった.md)）。

**営業時間については、上流も下流も「毎回入力する」とすでに書いていた。**

> **説明文に書かれた営業時間は、前回の値であって既定ではない。**日ごとの 4 時刻は**毎年変わる ◎**（作る側 21）。
> 毎回入力する（→ 上記「すでにあるもの」の表・候補 F の却下理由）
>
> — 6「希望時間の聞かれ方と変換規則」

**それでも、フォームに何を出すかは書いていなかった。**
下流（[`docs/tech-requirements.md`](../../tech-requirements.md) 4-3）は**転記を優先する**と決めており、
**4 の定義から作るフォーム**（→ [issue #144](https://github.com/jun-eg/school-festival-shift/issues/144)・[`src/build-form.js`](../../../src/build-form.js)）は
**前回の値をそのまま入る側に見せる形で入った。**

| 入る側に見えていたもの | 入っていた値 |
| --- | --- |
| **設問の題 4 つ** | `11月1日(準備日)` ／ `11月2日(学祭1日目)` ／ `11月3日(学祭2日目)` ／ `11月4日(片付け)`（**前回＝ 2025 年の日付**） |
| **説明文の営業時間** ◎ | 準備日 `8:00-21:00` ／ 1日目 `8:00-20:00` ／ 2日目 `8:00-20:00` ／ 片付け `8:00-15:00`（**前回の値**） |

**4-2 の「変わらないもの」の表は、日付と営業時間について何も言っていなかった。**

## 何が起きたか

**転記の器が、判断を上流に差し戻した。**
下流は「**揃えるのは『変える判断』であって転記ではない。揃えたいなら [`docs/design-doc.md`](../../design-doc.md) に戻して判断を起こす**」
（→ [`docs/tech-requirements.md`](../../tech-requirements.md) 4-3）と書いてあり、[issue #190](https://github.com/jun-eg/school-festival-shift/issues/190) がその 1 本である。

**担当者が決めた**（2026-09-21。issue #190 のコメント）。
**替える** ／ **出どころは条件入力** ／ **営業日・時間は先に入力してもらう必要がある** ／
**判定は「前回の値を入れたら 4 の表と一致する」でよい**、の 4 つである。

**列名を固定する案（`学祭1日目` のように日付を落とす）も担当者から挙がったが、採らなかった。**
**入る側が最初に見るのは題である**ことを、4-2 の Before = After のほうが上回ると読んだ（→ 下の「新しい結論」の却下側）。

## 新しい結論

**入る側に見える日付と営業時間は、今年の入力から出す。**

| 決めたこと | |
| --- | --- |
| **替えるか** | **替える。**設問の題の日付と、説明文に書かれた営業時間を、**今年の入力から出す** |
| **値の出どころ** | **条件入力の「日ごとの営業時刻」1 か所**（→ [`docs/tech-requirements.md`](../../tech-requirements.md) 5-1 の #1）。**別入力を立てない。****帯は `準備開始`〜`片付け終了`** |
| **担当者の操作** | **「日ごとの営業時刻」だけ、フォームを作る前に入れる**（→ 同 2 の一覧 3・5）。**入力の種類は増えない** — **順が前に出ただけ**である。**空のまま押されたら、作らずに名指しして止まる** |
| **列名の当て方** | **回答シートの列名は毎年変わる**（列名＝設問の題である）。**取り込みは位置で当てる** — タイムスタンプ ＋ 設問 9 つの並び（→ 同 5-1 の #6） |
| **仕様 #2 の判定** | **前回の日付（2025-11-01〜04）と営業時刻を条件入力に入れて**作ったフォームが、**4 の表と差分 0**（→ 同 5 の #2） |

**4-2 の Before = After の読み方が定まった。**
**「前回のフォームがそのまま再現されること」ではなく、「入る側がその年の正しい日付を見ること」が Before である。**
**前回の担当者は毎年フォームを作り直していた** ◎（作る側 ACTION 4）ので、**入る側が去年の日付を見たことは一度も無い。**
**前回の値を貼ったフォームのほうが、Before を壊す。**

**却下した側**（4 本。6 の新設節に表で残した）。

| 案 | 採らなかった理由 |
| --- | --- |
| **前回の値のまま複製する** | 入る側が去年の日付を見る。避けるには担当者が毎年手で直すことになり、**ACTION 4 の重さ ◎ が部分的に戻る** |
| **題から日付を落として固定する**（`準備日` ／ `学祭1日目` …） | **列名が固定でき、取り込みを列名で当てられる**が、**入る側が最初に見るのは題である。****列名は位置で当てれば足りる** |
| **フォームを作るときに日付と営業時間を別に聞く** | **同じ値を 2 か所に書かせる。**食い違いの正が決まらず、**入力の種類が増える**（達成条件 4） |
| **入力が空でも営業時間の行を落として作る** | **黙って中身を減らす。**説明文の営業時間は記録にある ◎ もので、**落とすこと自体が「変える判断」である** |

## 影響

- **6 に「入る側に見える日付と営業時間は、今年の入力から出す（スコープ内 2）」を新設**し、
  **決めたこと 5 行**と **却下した 4 案**を置いた
- **6「『渡らない ◎』資産をどう外したか」**の「転記する。変える判断をしない」に、**例外が 2 つ（締切と、この日付・営業時間）であることを 1 段足した**
- **6 スコープ内「作るもの」2** に、**日付と営業時間は複製しない**ことを書いた
- **4-2 の「変わらないもの」の表の直後**に、**日付と営業時間はこの表に入らない**ことと、**Before = After の読み方**を置いた
- **下流の [`docs/tech-requirements.md`](../../tech-requirements.md) が動いた。****あちらの更新ログはこの ADR を指す**
  （動いたのは上流の判断 1 つなので、`docs/ADR/tech-requirements/` は起こさない）
  - **4-1** — 題は「今年の日付 ＋ ラベル」で組む。**ラベル 4 つは転記、日付だけが入力から出る。**区画が 4 行でなければ止まる。**列名は毎年変わり、取り込みは位置で当てる**
  - **4-2** — 今年の値の出どころと、説明文に出す帯（`準備開始`〜`片付け終了`）
  - **5 の #2** — 判定が「**前回の値を入れて**突き合わせる」になった
  - **5-1 の #1・#6** — `日付` の行き先と、列名が毎年変わること
  - **2 の一覧 3・5** — **5 の「日ごとの営業時刻」だけが 3 より前に来る。番号は振り直していない**
  - **2 の止まる箇所に #9** — 空のまま押されたときに止まる
  - **8 の 5** — 依存に条件入力の区画が付いた
  - **9 に △ 12** — **4 日でない年のラベルの呼び名**（記録に無い。行き先は上流）

## 動いていないもの

- **1・2・3・5・7 は 1 行も動いていない。****達成条件 1〜4 も、スコープ内・スコープ外の線も動いていない**
- **4-2 の「変わらないもの」4 行（集める口・聞かれること 6 項目・配る口・手数）は 1 つも動いていない。**
  **入る側が答える中身も、聞かれ方も、手数も変わらない**
- **入力の種類は 6 のままである**（→ [`docs/tech-requirements.md`](../../tech-requirements.md) 5-1）。
  **増えたのは操作の順だけで、達成条件 4（要求するのは入力だけ ◎）は破っていない**
- **フォーム定義一式が転記であることは動いていない。****例外が 1 つ増えただけ**である
  （**エラーメッセージの表記揺れ ◎ は揃えないまま** → 同 4-3）
- **M1〜M6 の完了の定義も日付も動いていない。****M1 ② の入力は前回の値で作ったフォームなので、モック CSV の見出しも動かない**
- **6-1 の #1（フォームが「完成品の複製」に切り替わる可能性）に乗っている。**
  **定義から作らない形になれば、この判断ごと置き場を失う**（→ issue #190 の「6-1 の #1 が外れた場合」）
