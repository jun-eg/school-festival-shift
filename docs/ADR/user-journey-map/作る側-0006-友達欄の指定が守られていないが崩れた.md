# ADR 作る側-0006: 改善機会 28「友達欄の指定が守られていない ◎」が崩れた — 記録では書かれた分が全件指定どおりだった

- **Status**: 有効
- **Date**: 2026-09-17
- **対象**: docs/journey/作る側.md — 改善機会 28・29 / ACTION 4 / 「試したこと」の表
- **出典**: 希望収集フォームの設定と収集データ（保持者への聞き取りで形と件数のみ起こした） / issue #83

## それまでの結論

改善機会 28「フォームが友達欄に指定した学籍番号が、**守られていない** ◎」。
根拠は「指定どおりと分かるのは入る側 5 人のうち 1 人だけ → **入る側 (4/5) が指定と違う形**」。
**入る側 改善機会 3 の裏側**として、入る側の証言だけに立っていた。

「試したこと」の表では、正規表現バリデーションの効きを
「整備工程は軽くなった。**入力側で弾かれた人はいない → 入る側 (5/5)**」と書いていた。

## 何が起きたか

**記録を引いた**（→ [入る側-0012](入る側-0012-友達欄の指定が守られていないが崩れた.md)）。

友達欄は**任意項目**で、正規表現は **10 桁の英数字（カンマ区切りで複数可）しか通さない** ◎。
収集データ全 50 件の友達欄は **学籍番号 29 件・空欄 21 件**、**属性・個人名は 0 件** ◎。
**インタビューで属性・個人名に見えていた答えは、フォームに入力された値ではなかった。**

## 新しい結論

- 改善機会 28 →「友達欄は、**提出の 4 割強が空欄のまま出されている** ◎（記録 21/50）」。
  **書かれた分は全件が指定どおり**で、**落ちているのは書式ではなく入力そのもの**である
- 弾かれて空にしたのか最初から書かなかったのかは**記録では区別できない** △
- 改善機会 29 は **入る側 (1/5) のまま据え置く**。記録上の記入者はもう 1 人いる ◎ が、
  **その人が手間を口にしたかは聞いていない** △
- 「試したこと」の表の効きは、**友達欄に残った値が全件学籍番号だったこと** ◎ で裏が取れた。
  ただし「**弾かれた人はいない (5/5)**」は**自己申告**であり、**記録と食い違う人が 2 人いる** ◎

## 影響

- 改善機会 28 を書き直し、改善機会 29 の注意に △ を足す
- ACTION 4 の TASK LIST に正規表現の形と「友達欄は任意・複数可」を足し、
  IMPROVEMENT の「友達欄の指定が守られていない」を書き直す
- 「試したこと」の表の正規表現バリデーションの行を、記録と自己申告の両方が読める形に差し替える
