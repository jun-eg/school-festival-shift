# ADR — 判定が動いた記録

**成果物の本文は「今の結論」だけを持つ。** 結論がどう動いたか（それまでどう書いていたか・
何が起きて変わったか）は、**ここに 1 判定 1 ファイルで積む**。

本文に経緯を残すと、既存の全項目に「N 人目まではこうだった → 崩れた」が 1 段ずつ生えて、
**人を 1 人聞くたびに本文が伸びる**。かといって経緯は捨てられない
（「n=4 で確定と書いたものが n=5 で動いた」は、次に読む人が (n/m) をどこまで信用してよいかを決める材料になる）。
git log にはコミットメッセージの粒度しか残らず、**何が何に変わったか・なぜかは追えない**。

| 器 | 何を持つ |
| --- | --- |
| 成果物の本文（`docs/journey/<立場>.md` など） | **今の結論だけ** |
| `docs/ADR/<対象>/` | **判定が動いた記録**（それまでの結論 / 何が起きたか / 新しい結論 / 影響） |
| 成果物末尾の「更新ログ」節 | **索引** — 1 行（日付・動いたもの・ADR へのリンク） |

## 置き場所

```
docs/ADR/
├── README.md                    ← このファイル
├── _template.md                 ← ADR の雛形
└── user-journey-map/            ← ジャーニーマップの判定が動いた記録
    ├── 入る側-0001-<slug>.md
    ├── 入る側-0002-<slug>.md
    └── 作る側-0001-<slug>.md
```

**第 1 階層は対象**（＝ どの skill / どの成果物の話か）。

| フォルダ | 何を記録する場所か |
| --- | --- |
| `user-journey-map/` | `docs/journey/<立場>.md` の**判定が動いた記録**。記号（◎ / ○ / △）が変わった・(n/m) の読みが変わった・当初の想定が否定された・取り消された |

今後 `hmw/` `design-doc/` `interview-questions/` が増えても、**同じ形で第 1 階層に足す**。
**フォルダを足したら、この表にも 1 行足す。** ここが薄いと「なんの ADR か分からない」に戻る。

## ファイル名

`<立場>-<連番>-<slug>.md`

- **連番は立場ごとに 0001 から**振る。**欠番を詰めない・振り直さない**
- **立場をフォルダにせず、ファイル名の先頭に置く。** 立場は少数なので階層を 1 段増やすほどの量にならない。
  先頭に置けば `ls` で立場ごとに固まる
- `<立場>` 部分は対象によって変わる（`user-journey-map/` では `docs/journey/<立場>.md` の立場名）

## 本文からの参照の書き方

**`ADR 入る側-0001` と書く。** 番号だけでは対象が分からない。

## Status

| Status | 意味 |
| --- | --- |
| 有効 | この ADR の「新しい結論」が現在の結論である |
| 取り消し（`ADR <立場>-NNNN` が上書き） | 後続の ADR に上書きされた |

**判定は一度戻ることがある。** 上書きした ADR と上書きされた ADR は**相互にリンクする**
（上書きした側の「それまでの結論」に元の ADR を、上書きされた側の Status に新しい ADR を書く）。

## 書くタイミング

**本文を削る前に ADR を書く。** 先に本文から抜くと、抜いた瞬間に情報が消える。
