# 前回の確定シフト — 記録の実体

**ここは記録の実体の置き場である。** 前回（2025 年）の学祭の確定シフトを、
**担当者が割り当てを組むときに直接編集していた JSON 4 本 ◎** から転記したものを持つ。

**突き合わせる相手の隣に置いてある。** 同じディレクトリの
[`前回の確定シフト-モック-01.json`](前回の確定シフト-モック-01.json) 〜
[`-04.json`](前回の確定シフト-モック-04.json) が、ここに書かれた件数を全件再現している。

**判断はここに無い。** 「何を転記元にしたか」と「**変えないという判断**」（揃えない・振り直さない・畳まない・
数えない・型に乗らない・妥当性に使わない）は
[`docs/tech-requirements.md`](../docs/tech-requirements.md) の **4-5** が持つ。
**以下この文書では、それを「要件定義書」と呼ぶ。**

**この分担が動いた記録は、要件定義書の更新ログと**
[`docs/ADR/tech-requirements/`](../docs/ADR/tech-requirements/) **にある。**

**形骸化した文字列の中に、指定時刻だけが残っている**形になる。

## 同じ仮名が 2 人に当たっている — **モック化の副作用**

**4 名分 8 つの `memberId` は、8 人である ◎**（「**データをmock化した際のミス。実際は1:1の関係**」。2026-09-20）。
**1 人が 2 つのキーに割れているのではない** — **2 つの群の間に時間の重なりが 12 件あり、1 人では成り立たない。**

| 何が重なっているか | 件数 | 例 |
| --- | --- | --- |
| **一部だけ重なる**（**1 人では同時に居られない**） | **7** | `高木琴音` 11/2 `10:00-15:00 呼び込み` × `10:00-11:00 列整理` ／ `杉山美月` 11/2 `15:00-18:00 調理責任者` × `15:00-16:00 呼び込み` ／ `森田咲良` 11/4 `10:00-15:00 準備` × `13:00-15:00 準備` |
| **まったく同じ区間・同じ役割** | **5** | `杉山美月`・`高木琴音` が 11/2・11/3 の `18:00-20:00 片付け` に両方（4 件）／ `杉山美月` が 11/4 `08:00-15:00 準備` に両方 |

- **`長谷川蒼真` だけは 2 群が重なっていない**（① が 11/1 の 1 件、② が 11/3 の 3 件）。**それでも別人である ◎**（本人の確認は 4 組まとめてである）
- **この 12 件は、「同じ人が同じ枠に二重」に当たる 1 件**（→ 上の「揃っていないところ」の 6。**同じ `memberId` の中の重なり**）**とは別である**

**衝突しているのは確定シフト側だけである** ◎。**希望データ側では起きていない** —
**確定シフトに入っている 2 つの学籍番号のうち、希望データにも出てくるのは片方だけである** ◎
（**実データ（モック化前）で確認した**。2026-09-20 → [`docs/interviews/02-作る側.md`](../docs/interviews/02-作る側.md)）。
**同じ氏名の 2 行が希望データ側にもある 3 名**（`杉山美月`・`森田咲良`・`高木琴音`）**は、同じ人の出し直しである** —
**`実人数 39 人` ◎ と `出し直し 11 行` ◎ の検算は崩れていない。**

**人数が閉じる。**

| | 人数 |
| --- | --- |
| **確定シフト 40 人** | **氏名が一意な 32** ＋ **仮名が衝突している 8** |
| **そのうち希望を出している** | **36**（一意な 32 ＋ **衝突している 8 のうち 4**）◎ |
| **そのうち希望を出していない** | **4** ◎（**衝突している 4 組の、それぞれ片方**） |
| **希望データ 39 人 ◎** | **確定シフトに入っている 36** ＋ **入っていない 3**（`三浦朝陽`・`宮本芽依`・`白石悠真`）|

**40 ＝ 36 ＋ 4、39 ＝ 36 ＋ 3 で両側とも閉じる。**
**どの 4 人が出していないのかだけが決まらない**（→ 要件定義書 9 の △ 10）。
**出していない 4 人をどう入れたのかは ○ のままである** —「**希望出してないけどlineかなんかで聞いて割りあてた可能性はある**」。

## 準備・片付けの入り方 — **要件定義書の規則 3 と食い違う**

**11月2日・11月3日**（`準備` と `片付け` の両方が出てくる日）で、**規則 3 の ①〜⑤ が成り立っていない。**

| 何が起きているか | 11月2日 | 11月3日 |
| --- | --- | --- |
| **`準備` と `片付け` の両方に入っている人** | **7** | **7** |
| **他の役割はあるのに `準備` も `片付け` も無い人** | **5** | **9** |
| **他の役割が 1 つも無いのに `準備`／`片付け` に入っている人** | **2** | **3** |

**この 3 つは、「午前／午後」の境目をどこに置いても消えない。**
規則 3 の ②〜⑤ は、**どの枝を通っても 1 人に `準備` と `片付け` の両方を与えない**し、
**割り当てのある人には必ずどちらかを与え、割り当ての無い人にはどちらも与えない**からである。
**境目（`12:00` ◎）が決まっても、食い違いは残る。**

**3 つのうち、名前が付いたのは 1 つだけである**（2026-09-20 → [`docs/interviews/02-作る側.md`](../docs/interviews/02-作る側.md)）。

| 食い違い | 担当者が何と言ったか |
| --- | --- |
| **`準備` と `片付け` の両方**（7・7） | **「削り忘れ」** ◎ |
| **どちらも無い**（5・9） | **「希望時間的にそうだったのか、ただシフト組的に考慮しきれなかったのか」** — **決まらない** |
| **準備／片付けだけ**（2・3） | **「希望時間がそこしか無かったからか、他の役割の入れ忘れ」** — **決まらない** |

**この 3 つの数字をどう扱うか**（取り消さない・△ にしない・判定に効かせない）**は要件定義書 4-5 が持つ。**
