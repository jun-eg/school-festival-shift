# scripts — 数え直す手の置き場

**ここにあるのは、データから数え直して宣言と突き合わせる手である。** 実装（GAS）ではない。
**データそのものは [`data/`](../data/) が持つ。混ぜない。**
**型や規則が要る手は、[`src/`](../src/) のものをそのまま走らせる。ここで書き直さない**
（**書き直した型に乗っても、判定の答えにならない**）。

## 件数の検算

```
node scripts/件数の検算.mjs
```

**依存はゼロである**（Node の標準だけを使う）。**何も書き換えない。読むだけである。**
**全件一致なら終了コード 0、1 つでも外れたら 1 で落ちる。**

| | |
| --- | --- |
| **入力** | [`data/`](../data/) の 5 本だけ（確定シフトのモック 4 本 ＋ 希望データのモック 1 本） |
| **期待値** | [`件数の期待値.json`](件数の期待値.json)。**ここが原本である。スクリプトは期待値を持たない** |
| **見るもの** | ① data から数え直した値が期待値と一致するか ② その数字が本文に載っているか ③ 数え方の宣言を頭に出す |

**本文の側は、数字が載っていることしか見ない。解析はしない。**
そのかわり、**本文の数字が書き換わったのに期待値を直し忘れた場合も落ちる** —
[`docs/tech-requirements.md`](../docs/tech-requirements.md) と [`data/前回の確定シフト.md`](../data/前回の確定シフト.md) が
同じ数字を二重に持っていることへの見張りを兼ねる。

## M1 ① の判定

```
node scripts/M1①の判定.mjs
```

**[`docs/tech-requirements.md`](../docs/tech-requirements.md) 7 の M1 ① そのものである** —
**前回の確定シフトのモック 4 本が 5-1 の型に乗るかを見て、乗らなかった行を数える。**
**合格の線は 0 行。**0 行なら終了コード 0、1 行でもあれば 1 で落ちる。**何も書き換えない。読むだけである。**

| | |
| --- | --- |
| **入力** | [`data/`](../data/) の確定シフトのモック 4 本 ＋ **型そのもの**（[`src/input-types.js`](../src/input-types.js)・[`src/sheet-layout.js`](../src/sheet-layout.js)） |
| **宣言** | [`M1①の宣言.json`](M1①の宣言.json)。**ここが原本である。スクリプトは線も置き方も持たない** |
| **数えるもの** | **5-1 の型に乗らなかった行**（**1 つだけ**）。**日ごとと通しで出す** — **4 日とも通しで判定できる**（→ 7） |
| **当て方** | `date` ＋ 区間 ＋ `role` を**型 #2／#4 の行の形**に、`date` ＋ 区間を**型 #1 の 30 分枠**に、`memberId` を**型 #6 の識別キー**に当てる |
| **見ないもの** | `slotId`・氏名・`creationResult`（**型に無い項目**）／ 学年・調理可否（**確定シフト側に当たる項目が無い**） |

**型は書き直さない。**[`src/input-types.js`](../src/input-types.js) を `SpreadsheetApp` 無しでそのまま走らせて、
確定シフトの行を通す。**止まったら、型が言った理由ごと「乗らなかった行」に数える。**

**数えるのは生成した案ではない。****前回の記録は入力で、見るのは型に乗るかだけである**（→ 5-4）。
**前回の記録が規則 3 の ①〜⑤ を満たしていないこと ◎ は、ここに効かない**
（**規則が違ったのではなく、前回の実行が規則に届かなかった** → [`ADR tech-requirements/0003`](../docs/ADR/tech-requirements/0003-準備と片付けの規則が降りた先から戻りM2の数えに入った.md)）。
**違反を数えるのは [`src/count-violations.js`](../src/count-violations.js) の側で、入力は生成した案である。**

**端が枠に揃わない行は、乗った側でも内訳に出す** —
**`2025-11-03 12:00-12:40` の `クリーンパトロール` 3 行**は、**指定枠と同じ向き（重なる枠を取る）で `12:00` と `12:30` の 2 枠に乗る**（→ 7）。

## いつ走らせるか

**手で 1 コマンドである。CI にも hook にも乗せていない**（実装が入って CI ができたら、そのときに乗せる
→ [`docs/tech-requirements.md`](../docs/tech-requirements.md) 8）。

| 手 | 走らせる PR |
| --- | --- |
| **件数の検算** | [`data/`](../data/) を触った PR ／ [`docs/tech-requirements.md`](../docs/tech-requirements.md) の **4-5・7** か [`data/前回の確定シフト.md`](../data/前回の確定シフト.md) の**件数を触った PR** |
| **M1 ① の判定** | [`data/`](../data/) の確定シフトを触った PR ／ **[`src/input-types.js`](../src/input-types.js)・[`src/sheet-layout.js`](../src/sheet-layout.js) を触った PR**（**型が動いたら、前回の記録が乗るかも動く**）／ [`docs/tech-requirements.md`](../docs/tech-requirements.md) の **5-1・7** を触った PR |

**走らせたら、出力を PR に貼る。**

## 数えた結果が外れたら

**データと本文のどちらが正かは、この手は決めない。** 落ちたことだけを言う。
**期待値を書き換えて通すのは最後である** — 先に「data と本文のどちらが動いたのか」を見る。

**M1 ① の判定で乗らなかった行が出たときも同じである。****型を直すのか記録を読み直すのかを、この手は決めない。**
**どの行がどの理由で乗らなかったかと、分かれ道 3 つを出して止まる**（**原本は
[`M1①の宣言.json`](M1①の宣言.json) の `乗らなかった行が出たら`**）。

| 疑う先 | どういうときか | 動かす先 |
| --- | --- | --- |
| **記録の読み直し** | 乗らなかった行が [`data/前回の確定シフト.md`](../data/前回の確定シフト.md) の「揃っていないところ」と重なるとき | **転記のほう。**ただし**揃えない・振り直さない・畳まない**（→ 4-5・7） |
| **型を直す** | 記録がそのまま転記されていて、それでも型が受け取れない形のとき | **[`docs/tech-requirements.md`](../docs/tech-requirements.md) の 5-1（判断）→ ADR ＋ 更新ログ → [`src/input-types.js`](../src/input-types.js)。****判断を動かさずにコードだけ直さない** |
| **判定の置き方を直す** | 記録にも型にも触らずに消えるとき（営業時刻の置き方・重なる枠を取る向き） | **[`M1①の宣言.json`](M1①の宣言.json)。**変えた置き方と、なぜ変えたかを併記する |

## 数え方を足すとき

**期待値と数え方は [`件数の期待値.json`](件数の期待値.json) に、判定の線と置き方は [`M1①の宣言.json`](M1①の宣言.json) に書く。**
**スクリプトの中に数字を書かない。**
**宣言しないと数えられないもの**（畳み方・重なりの定義・一致の定義・記録に無い値の置き方）は、
**決めた側と、なぜ宣言が要るかを `数え方`／`宣言` に足す**
（→ [`.claude/skills/tech-requirements/SKILL.md`](../.claude/skills/tech-requirements/SKILL.md) 手順 7）。
