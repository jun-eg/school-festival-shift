# scripts — 数え直す手の置き場

**ここにあるのは、データから数え直して宣言と突き合わせる手である**（**秒を測る手も、線を宣言が持つ点は同じである**）。
実装（GAS）ではない。
**データそのものは [`data/`](../data/) が持つ。混ぜない。**
**型や規則が要る手は、[`src/`](../src/) のものをそのまま走らせる。ここで書き直さない**
（**書き直した型に乗っても、判定の答えにならない**）。

## 件数の検算

```
node scripts/件数の検算.mjs
```

**依存はゼロである**（Node の標準だけを使う）。**何も書き換えない。読むだけである。**
**全件一致なら終了コード 0、1 つでも外れたら 1 で落ちる。**

| | |
| --- | --- |
| **入力** | [`data/`](../data/) の 5 本だけ（確定シフトのモック 4 本 ＋ 希望データのモック 1 本） |
| **期待値** | [`件数の期待値.json`](件数の期待値.json)。**ここが原本である。スクリプトは期待値を持たない** |
| **見るもの** | ① data から数え直した値が期待値と一致するか ② その数字が本文に載っているか ③ 数え方の宣言を頭に出す |

**本文の側は、数字が載っていることしか見ない。解析はしない。**
そのかわり、**本文の数字が書き換わったのに期待値を直し忘れた場合も落ちる** —
[`docs/tech-requirements.md`](../docs/tech-requirements.md) と [`data/前回の確定シフト.md`](../data/前回の確定シフト.md) が
同じ数字を二重に持っていることへの見張りを兼ねる。

**入力は「複製したフォーム」ではない。** **テンプレートのスクリプトが 4 の定義から作ったフォームの回答スプレッドシートである**（→ 6 の #6）。
**完成品を複製した場合とは、回答先の紐付けが手作業で残るかどうかが変わる**（→ 経路の段 4）。

**実装は書き直さない。**[`src/`](../src/) の 13 ファイルを 1 つの文脈にそのまま読み込んで、
**メニューが出るところから型 #6 が出るところまでを 1 本通す。**
**偽で置き換えるのは Google 側の器だけである**（`FormApp` ／ `SpreadsheetApp` ／ `Utilities` ／ `HtmlService`）。
**器が偽である以上、ここで分かるのは経路だけである** — **本物の上で通ったかは実機の記録が持つ。**

**段で数えるのはなぜか。** **手が入りうるのは段と段のつなぎ目だからである。**
**つなぎ目を全部並べて、1 つずつ「スクリプトが運べたか」を見る** —
**止まる／運んだものが次の段の形になっていない／そもそも押す口が無い、のどれかなら、そこに担当者の手が入る。**

## 生成の所要時間の実測

```
node scripts/生成の所要時間.mjs
```

**[`docs/tech-requirements.md`](../docs/tech-requirements.md) 6-1 の #2 の前提そのものである** —
**「生成が、スクリプトの実行時間の上限の中で終わる」かを、秒を測って見る。**
**合格の線は 360 秒**（Apps Script の 1 実行あたりの上限 6 分）。**中央値が越えたら終了コード 1 で落ちる。**
**何も書き換えない。読むだけである。**

| | |
| --- | --- |
| **入力** | [`data/前回の希望データ-モック.csv`](../data/前回の希望データ-モック.csv) の **50 行** ＋ **実装そのもの**（[`src/`](../src/) の 9 ファイル）＋ 条件入力の 5 区画（**宣言が持つ**） |
| **宣言** | [`生成の所要時間の宣言.json`](生成の所要時間の宣言.json)。**ここが原本である。スクリプトは上限も置き方も持たない** |
| **測るもの** | **[`src/core.js`](../src/core.js) の `build` を 1 周する時間（秒）**と、**段ごとの内訳**。**20 回回して中央値・最小・最大を出す** |
| **あわせて出すもの** | **回答の行を複製して人数を増やした側**（枠は 88 のまま）。**実機が何倍遅ければ上限に当たるか**を、余裕の倍率で出す |
| **測らないもの** | **`SpreadsheetApp` の往復**（殻の側。**実機でしか分からない** → [`src/real-device-log.md`](../src/real-device-log.md)）／ **実機（Apps Script の V8）での速さ** ／ **指標を出す段**（まだ中身が無い → [#154](https://github.com/jun-eg/school-festival-shift/issues/154)）／ **案の中身**（違反 0 か・名指しされているかは **M2 の判定**である → [#153](https://github.com/jun-eg/school-festival-shift/issues/153)） |

**1 実行まるごとを測る。****生成の段だけを測らない** —
**上限に当たるのは、メニューを 1 回押したときに走る 1 実行である**（→ 6 の #4）ので、
**同じ 1 実行の中にある他の段を落とすと、比べる相手が変わる。**
**そのうえで段ごとの内訳を出すのは、当たったときに見る先が分かれるからである** —
**生成の段が重ければ方式の話**（6 の #3）**になり、他の段が重ければそこの話になる。**

**終端 ≤ 始端を書いた 3 人は、展開の段が名指しして止まる**（→ 3 の境界値・[`src/expand.js`](../src/expand.js)）。
**外さないと 1 周が途中で止まって時間が測れない**ので、**外してから回し、外した人を名指しで出す**
（**39 人のうち 36 人で組んでいる**）。

**時間の値より先に、入力が本文の規模と同じかを見る**（**50 行 → 39 人 → 36 人 ／ 88 枠（26/24/24/14）／ のべ 704**
→ 6 の #3 の理由 ②）。**入力が違えば、時間は比べる相手にならない。**

| **線を当てないもの** | **未充足そのもの**（**0 でなくてよい** → 5-4）／ **所要時間**（**秒で残すのが受け入れ条件で、上限との突き合わせは [`生成の所要時間.mjs`](生成の所要時間.mjs) が持つ**） |
| **数えに入らないもの** | **規則 3 の ⑥**（複数日で偏らせない。**上流の △ 5 待ち** → 5-4 の但し書き）／ **指標**（まだ中身が無い → [#154](https://github.com/jun-eg/school-festival-shift/issues/154)）／ **実機で同じ案が出るか**（→ [`src/real-device-log.md`](../src/real-device-log.md)）／ **前回の確定シフトが規則を満たしているか**（→ **M1 ① の判定**） |

**未充足の行をそのまま数えない。** **名指しした側に名指しを採点させることになり、何件出ても 0 件になる。**
**案の側の不足を数え直して、検証結果の行と両方向で突き合わせる** —
**不足が有るのに名指しが無い ／ 名指しは有るが `あと何人` が食い違う ／ 不足が無いのに名指しが有る、の 3 つを出す。**
**要る人数は [`src/name-unmet.js`](../src/name-unmet.js) の `requiredAt` が、置いた行の読み方は
[`src/count-violations.js`](../src/count-violations.js) の `readAssignments` が持つ**（**書き直さない**）。
**数えて突き合わせるところだけが、この手の仕事である。**

**件数とは別に、2 つの数えが同じ需要に乗っているかを見る** —
**需要のべ ＝ 需要の枠に置いた ＋ `あと何人` の合計**、および**要る人数より多く置いた枠が 0**。
**揃わなければ、0 件が出ていても判定として信用できないので、件数の合否を言わずに落ちる。**

**規則 3 の ⑥ を数えていないことは、出力に出す**（**原本は
[`src/count-violations.js`](../src/count-violations.js) の `violationsNotCounted`**）。
**①〜⑤ が入ったことで M2 の合格の線は動いている**ので、**含まないことを隠さない**のがここの仕事である（→ 5-4）。

**終端 ≤ 始端を書いた 3 人は、展開の段が名指しして止まる**（→ 所要時間の実測と同じ扱い）。
**外してから組み、外した人を名指しで出す**（**39 人のうち 36 人で組んでいる**）。

**件数より先に、入力が本文の規模と同じかを見る**（**50 行 → 39 人 → 36 人 ／ 88 枠（26/24/24/14）／ のべ 704**）。
**違う入力で 0 件でも、M2 の答えにならない。**

## 数えた結果が外れたら

**データと本文のどちらが正かは、この手は決めない。** 落ちたことだけを言う。
**期待値を書き換えて通すのは最後である** — 先に「data と本文のどちらが動いたのか」を見る。

**M1 ① の判定で乗らなかった行が出たときも同じである。****型を直すのか記録を読み直すのかを、この手は決めない。**
**どの行がどの理由で乗らなかったかと、分かれ道 3 つを出して止まる**（**原本は
[`M1①の宣言.json`](M1①の宣言.json) の `乗らなかった行が出たら`**）。
