# scripts — 数え直す手の置き場

**ここにあるのは、データから数え直して宣言と突き合わせる手である**（**秒を測る手も、線を宣言が持つ点は同じである**）。
実装（GAS）ではない。
**データそのものは [`data/`](../data/) が持つ。混ぜない。**
**型や規則が要る手は、[`src/`](../src/) のものをそのまま走らせる。ここで書き直さない**
（**書き直した型に乗っても、判定の答えにならない**）。

**走らせる手そのものではないファイルが 2 本ある。**

| ファイル | 何を持つか |
| --- | --- |
| [`前回の5時刻.mjs`](前回の5時刻.mjs) | **5 時刻の算出**（手としても走るが、[`M2の判定.mjs`](M2の判定.mjs) などが中から呼ぶ） |
| [`判定の入力.mjs`](判定の入力.mjs) | **M2 と同じ入力を組む手**（[`M2の判定.mjs`](M2の判定.mjs) と [`まとまりと散らし.mjs`](まとまりと散らし.mjs) と [`M4の判定.mjs`](M4の判定.mjs) が読む）。**値を 1 つも持たない** — 置き方の原本は [`M2の宣言.json`](M2の宣言.json) である。**別々に入力を組むと、件数を並べて読めなくなる** |

## 前回の 5 時刻の算出

```
node scripts/前回の5時刻.mjs
```

**M2 の側の条件入力の「日ごとの営業時刻」を、[`data/`](../data/) の前回の確定シフトから算出する手である**
（→ [`docs/tech-requirements.md`](../docs/tech-requirements.md) 7 の「前回の 5 時刻の置き方」）。
**5 時刻は入力の行としては記録に無いが、171 行を日と役割で束ねると帯が読める。**
**何も書き換えない。読むだけである。**

| | |
| --- | --- |
| **入力** | [`data/`](../data/) の確定シフトのモック 4 本だけ。**読むのは `date`・`start`・`end`・`role` の 4 つ**（`slotId` も `memberId` も読まない） |
| **宣言** | [`前回の5時刻の宣言.json`](前回の5時刻の宣言.json)。**ここが原本である。スクリプトは規則も時刻も持たない** |
| **出すもの** | **日ごとの 5 時刻**と、**値の出どころ**（**どの日の何行のうち、どの行から出たか**）と、**刻んだ枠の帯ごとの内訳** |
| **見るもの** | ① 算出した値が宣言の期待値と同じか ② 30 分に乗っているか・早い順か・学祭 2 日で 3 帯とも立っているか ③ `片付け終了` が 4-2 の営業時間 ◎ と揃っているか |

**読む側は [`M2の判定.mjs`](M2の判定.mjs) と [`生成の所要時間.mjs`](生成の所要時間.mjs) である。**
**両方がここを呼ぶので、秒と件数が同じ案の上で読める。**
**値を宣言に焼いていない** — **焼くと、[`data/`](../data/) が動いても気づけない。**
**宣言が持つのは算出の規則と、data が動いたことに気づくための期待値である**（→ [`件数の期待値.json`](件数の期待値.json) と同じ置き方）。

**M1 ① は別の置き方のままである**（**1 日を 1 本の帯として刻む** → [`M1①の宣言.json`](M1①の宣言.json)）。
**M1 ① が見るのは型に乗るかだけで、帯の内訳（どの枠が準備の帯か）を見ないので、変える理由が無い。**
**M2 は帯の内訳を見る** — **規則 3 の ①〜⑤ は「その人のその日が準備の帯か片付けの帯か」で決まる**ので、
**1 本の帯にすると準備帯が 0 枠になり、②（午前だけ → 準備）が一度も試されないまま違反 0 が出る**
（→ [`ADR tech-requirements/0007`](../docs/ADR/tech-requirements/0007-前回の5時刻を確定シフトから算出しM2の判定入力に入れた.md)）。

**記録の食い違いをどう読むかは、宣言の `決め` が持つ** — **`2025-11-04` の役割名（全部 `準備`）を文字どおり読むことと、
`準備` の行しか無い日は調理帯も片付け帯も 0 枠になることである。****記録そのものは 1 文字も書き換えない。**

## 生成の所要時間の実測

```
node scripts/生成の所要時間.mjs
```

**[`docs/tech-requirements.md`](../docs/tech-requirements.md) 6-1 の #2 の前提そのものである** —
**「生成が、スクリプトの実行時間の上限の中で終わる」かを、秒を測って見る。**
**合格の線は 360 秒**（Apps Script の 1 実行あたりの上限 6 分）。**中央値が越えたら終了コード 1 で落ちる。**
**何も書き換えない。読むだけである。**

| | |
| --- | --- |
| **入力** | [`data/前回の希望データ-モック.csv`](../data/前回の希望データ-モック.csv) の **50 行** ＋ **実装そのもの**（[`src/`](../src/) の 9 ファイル）＋ 条件入力の 6 区画（**「日ごとの営業時刻」は [`前回の5時刻.mjs`](前回の5時刻.mjs) が算出する。残りは宣言が持つ**） |
| **宣言** | [`生成の所要時間の宣言.json`](生成の所要時間の宣言.json)。**ここが原本である。スクリプトは上限も置き方も持たない** |
| **測るもの** | **[`src/core.js`](../src/core.js) の `build` を 1 周する時間（秒）**と、**段ごとの内訳**。**20 回回して中央値・最小・最大を出す** |
| **あわせて出すもの** | **回答の行を複製して人数を増やした側**（枠は 88 のまま）。**実機が何倍遅ければ上限に当たるか**を、余裕の倍率で出す |
| **測らないもの** | **`SpreadsheetApp` の往復**（殻の側。**実機でしか分からない** → [`src/real-device-log.md`](../src/real-device-log.md)）／ **実機（Apps Script の V8）での速さ** ／ **指標を出す段**（まだ中身が無い → [#154](https://github.com/jun-eg/school-festival-shift/issues/154)）／ **案の中身**（違反 0 か・名指しされているかは **M2 の判定**である → [#153](https://github.com/jun-eg/school-festival-shift/issues/153)） |

**1 実行まるごとを測る。****生成の段だけを測らない** —
**上限に当たるのは、メニューを 1 回押したときに走る 1 実行である**（→ 6 の #4）ので、
**同じ 1 実行の中にある他の段を落とすと、比べる相手が変わる。**
**そのうえで段ごとの内訳を出すのは、当たったときに見る先が分かれるからである** —
**生成の段が重ければ方式の話**（6 の #3）**になり、他の段が重ければそこの話になる。**

**終端 ≤ 始端を書いた 3 人は、展開の段が名指しして止まる**（→ 3 の境界値・[`src/expand.js`](../src/expand.js)）。
**外さないと 1 周が途中で止まって時間が測れない**ので、**外してから回し、外した人を名指しで出す**
（**39 人のうち 36 人で組んでいる**）。

**時間の値より先に、入力が本文の規模と同じかを見る**（**50 行 → 39 人 → 36 人 ／ 88 枠（26/24/24/14）／ のべ 1038**
→ 6 の #3 の理由 ②）。**入力が違えば、時間は比べる相手にならない。**

| | |

| **線を当てないもの** | **未充足そのもの**（**0 でなくてよい** → 5-4）／ **所要時間**（**秒で残すのが受け入れ条件で、上限との突き合わせは [`生成の所要時間.mjs`](生成の所要時間.mjs) が持つ**） |
| **数えに入らないもの** | **規則 3 の ⑥**（複数日で偏らせない。**上流の △ 5 待ち** → 5-4 の但し書き）／ **指標**（M2 の線に入らない。入るのは M3 である → [#154](https://github.com/jun-eg/school-festival-shift/issues/154)）／ **実機で同じ案が出るか**（→ [`src/real-device-log.md`](../src/real-device-log.md)）／ **前回の確定シフトが規則を満たしているか**（→ **M1 ① の判定**） |

**未充足の行をそのまま数えない。** **名指しした側に名指しを採点させることになり、何件出ても 0 件になる。**
**案の側の不足を数え直して、検証結果の行と両方向で突き合わせる** —
**不足が有るのに名指しが無い ／ 名指しは有るが `あと何人` が食い違う ／ 不足が無いのに名指しが有る、の 3 つを出す。**
**要る人数は [`src/name-unmet.js`](../src/name-unmet.js) の `requiredAt` が、置いた行の読み方は
[`src/count-violations.js`](../src/count-violations.js) の `readAssignments` が持つ**（**書き直さない**）。
**数えて突き合わせるところだけが、この手の仕事である。**

**件数とは別に、2 つの数えが同じ需要に乗っているかを見る** —
**需要のべ ＝ 需要の枠に置いた ＋ `あと何人` の合計**、および**要る人数より多く置いた枠が 0**。
**揃わなければ、0 件が出ていても判定として信用できないので、件数の合否を言わずに落ちる。**

**規則 3 の ⑥ を数えていないことは、出力に出す**（**原本は
[`src/count-violations.js`](../src/count-violations.js) の `violationsNotCounted`**）。
**①〜⑤ が入ったことで M2 の合格の線は動いている**ので、**含まないことを隠さない**のがここの仕事である（→ 5-4）。

**終端 ≤ 始端を書いた 3 人は、展開の段が名指しして止まる**（→ 所要時間の実測と同じ扱い）。
**外してから組み、外した人を名指しで出す**（**39 人のうち 36 人で組んでいる**）。

**件数より先に、入力が本文の規模と同じかを見る**（**50 行 → 39 人 → 36 人 ／ 88 枠（26/24/24/14）／ のべ 1038**）。**のべはもとごとの内訳（必要人数 1026 ／ 委員会の指定枠 12）まで数え直す。**
**違う入力で 0 件でも、M2 の答えにならない。**

**準備・片付けは帯の中にしか置かれない**（→ 5-5）。**帯は日ごとの 5 時刻から決まるので、
その日の準備帯が 0 枠なら `準備` は 1 件も出ない。****5 時刻を [`data/`](../data/) から算出しているのはこのためである**
（→ 上の「前回の 5 時刻の算出」・[`ADR tech-requirements/0007`](../docs/ADR/tech-requirements/0007-前回の5時刻を確定シフトから算出しM2の判定入力に入れた.md)）。
**役割ごとの件数は、0 件の役割も落とさずに出す** — **出なかったことが読めないと、理由をたどる先が無い。**

**実機で同じ件数になるかは、この手が持たない** — **[`src/real-device-log.md`](../src/real-device-log.md) の項目 15 が持つ**
（**2026-09-22 に 2 回見た。1 本の帯の入力で 660 行、算出した 5 時刻の入力で 681 行。どちらも手元と同じで、案の指紋も一致した**）。
**ここが回しているのは手元の Node である。**
